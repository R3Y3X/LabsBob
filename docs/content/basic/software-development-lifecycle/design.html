Diseño ~20 min Ask / Plan · Arquitecto draw.io

Fase 2 — Diseño: diagramación con draw.io

Convierte el plan aprobado en un contrato visual: diagrama de contexto/contenedores (C4 ligero) o flujo de API en draw.io / diagrams.net. Bob te ayuda a especificar el diagrama; tú lo materializas en la herramienta para que Agent Mode implemente sin ambigüedad.

Contexto de perfil

Diseñador

UX/flujo de usuario. Referencia: Figma, Miro.

Arquitecto

Límites del sistema y componentes. Referencia: draw.io, Lucidchart, Swagger.

Paso a paso

Paso 1 — Pedir la especificación del diagrama

En Ask o Plan, pide a Bob una especificación lista para dibujar (no código).

Prompt — especificación draw.io

Con base en el plan aprobado de la API de todos, genera una especificación
de diagrama para draw.io con:

1. Diagrama de contexto (usuario, API, base de datos en memoria/archivo)
2. Diagrama de contenedores: rutas FastAPI, modelos Pydantic, capa de tests
3. Flujo de secuencia: crear todo → listar → actualizar → eliminar
4. Lista de formas/etiquetas exactas a colocar en cada caja
5. Criterios de calidad del diagrama (nombres claros, sin cajas huérfanas,
   flechas con verbos, leyenda de colores)

Formato: lista numerada lista para copiar a diagrams.net.
No generes código fuente todavía.

Paso 2 — Construir el diagrama en draw.io

  1. Abre app.diagrams.net
  2. Crea un diagrama en blanco (Device-independent)
  3. Usa la especificación de Bob: cajas = componentes, flechas = llamadas
  4. Exporta PNG y guarda también el .drawio en el repo (p. ej. docs/architecture.drawio)

Checklist de buen output

  • Cada endpoint del plan aparece en el diagrama
  • Hay un camino feliz y un camino de error (404/validación)
  • Los nombres coinciden con el árbol de archivos del plan

Paso 3 — Validar el diagrama con Bob

Prompt — revisión de arquitectura

Voy a pegar la descripción / export del diagrama draw.io.
Compara con el plan aprobado e indica:
1. Inconsistencias (componentes en el plan que faltan en el diagrama)
2. Over-engineering (cajas que no aportan al MVP)
3. Riesgos de implementación
4. Lista corta de "reglas de implementación" para Agent Mode
