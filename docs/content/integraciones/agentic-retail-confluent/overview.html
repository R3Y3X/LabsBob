🌐 IBM Cloud / Watson ⬛ Terminal ⚙ Config

Fase 1. Inspección de instancia y acceso SSH

Antes de ejecutar cualquier script necesitas identificar la IP pública de tu VM y verificar que la clave SSH tiene los permisos correctos.

⚙ Config Verificar la instancia en IBM Cloud

  1. Ingresa al panel de control de tu instancia asignada en IBM Cloud / IBM TechZone.
  2. Copia la IP Pública (o Hostname) de la máquina virtual — la necesitarás en todos los pasos siguientes.
  3. Descarga o copia el contenido de tu clave privada SSH (.pem) entregada por el instructor.
📸 [IMAGEN 1.1] — Dashboard de la instancia en IBM Cloud: resalta la IP pública y la sección de descarga de la llave SSH

Con la IP obtenida, verifica el acceso SSH desde tu terminal local:

# Guarda la clave en la carpeta del lab
cp ~/Downloads/cflt-vsi-key.pem Lab1/inventory-pipeline/cflt-vsi-key.pem

# Asigna permisos de solo lectura al propietario
chmod 600 Lab1/inventory-pipeline/cflt-vsi-key.pem

# Verifica la conexión — debe responder "ok"
ssh -i Lab1/inventory-pipeline/cflt-vsi-key.pem root@<IP_DE_LA_MAQUINA> 'echo ok'

✓ Checkpoint 1

  • El comando SSH responde ok sin errores de permisos (Permission denied o Unprotected private key file).
  • La IP pública está anotada y lista para usarse en los pasos siguientes.

Confluent Cloud — sin VM local

En el entorno Cloud no se requiere acceso SSH. Continúa directamente con los prerrequisitos de la siguiente sección.

Prerrequisitos

⚙ Config Antes de empezar — VM + .env

  1. Guarda la clave cflt-vsi-key.pem (entregada por el instructor) dentro de Lab1/inventory-pipeline/.
  2. Copia la plantilla: cp .env.example .env y rellena SSH_HOST, SSH_KEY y las contraseñas del cluster con los valores que entregó el instructor.
  3. Verifica acceso SSH: ssh -i cflt-vsi-key.pem root@<VM_IP> 'echo ok' — debe responder ok.

🤖 Bob (IA) Automatizar la configuración completa — System Prompt maestro

Abre Bob en Agent Mode y pega primero el siguiente System Prompt maestro. Reemplaza los valores entre <...> con tus datos reales:

🤖 Prompt para Bob — System Prompt maestro (SSH + setup.sh)
Hola Bob, serás mi asistente de infraestructura para este workshop de Event Streaming. Aquí tienes mis accesos y parámetros: - IP del Host: <IP_PUBLICA_VM> - Usuario SSH: root - Contenido de la Clave Privada (guardar como cflt-vsi-key.pem): -----BEGIN RSA PRIVATE KEY----- <PEGA_AQUI_TU_CLAVE_PRIVADA_PEM> -----END RSA PRIVATE KEY----- Instrucciones para ti: 1. Crea el archivo 'Lab1/inventory-pipeline/cflt-vsi-key.pem' con la clave provista. 2. Aplica `chmod 600 Lab1/inventory-pipeline/cflt-vsi-key.pem`. 3. Verifica la conexión SSH con: ssh -i Lab1/inventory-pipeline/cflt-vsi-key.pem root@<IP_PUBLICA_VM> 'echo ok' 4. Revisa el archivo 'Lab1/inventory-pipeline/.env.example', crea el '.env' con los valores que te indique el instructor y confirma los parámetros aplicados.

✓ Checkpoint 3

  • Bob confirma que el archivo cflt-vsi-key.pem fue creado con permisos 600.
  • Bob confirma que la conexión SSH responde ok y que el .env está listo.

Si prefieres configurar el .env manualmente, usa el siguiente prompt:

🤖 Prompt para Bob — configurar .env
Tengo un lab de Confluent Platform en una VM de IBM TechZone. Necesito crear el archivo .env en Labs-tech-summit/ con estos valores: SSH_HOST=root@<PEGA_IP_DE_VM> SSH_KEY=Lab1/inventory-pipeline/cflt-vsi-key.pem BOOTSTRAP_SERVERS=kafka.confluent.svc.cluster.local:9092 KSQLDB_ENDPOINT=http://ksqldb.confluent.svc.cluster.local:8088 KSQLDB_ENDPOINT_EXTERNAL=https://<PEGA_IP_DE_VM>/ksqldb KSQLDB_USERNAME=admin KSQLDB_PASSWORD=<PEGA_CONTRASEÑA_KSQLDB> KSQLDB_API_KEY=admin KSQLDB_API_SECRET=<PEGA_CONTRASEÑA_KSQLDB> KAFKA_SASL_USERNAME=kafka-admin KAFKA_SASL_PASSWORD=<PEGA_CONTRASEÑA_KAFKA> KAFKA_SECURITY_PROTOCOL=SASL_SSL KAFKA_SASL_MECHANISM=PLAIN Crea el archivo .env con estos valores. Asegúrate de que no se commitee (verifica .gitignore).

⚙ Config Antes de empezar — Confluent Cloud + .env

  1. Recibe de tu instructor el archivo .env con BOOTSTRAP_SERVERS, KAFKA_API_KEY y KAFKA_API_SECRET.
  2. Cópialo a la raíz de Labs-tech-summit/.
  3. Inicia sesión en confluent.cloud y selecciona el cluster que indicó el instructor.
