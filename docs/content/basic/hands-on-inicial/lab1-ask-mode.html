Lab 1 — Ask Mode

Usa Ask para entender un proyecto de e-commerce y obtener explicaciones antes de decidir cualquier cambio.

0cambios de implementación
4consultas guiadas
1propuesta de README

Qué vas a lograr

  • Seleccionar Ask Mode para analizar código existente.
  • Identificar la arquitectura y los riesgos de un controlador.
  • Pedir una propuesta de README y comprobar que la respuesta tiene el alcance solicitado.

Cuándo usar Ask Mode

?

Entender antes de cambiar

Ask Mode sirve para preguntas, análisis, recomendaciones y documentación sobre tu workspace. Úsalo cuando necesitas comprender el código sin iniciar una tarea de implementación.

Permisos y cambios

Confirma siempre el modo que aparece en tu chat y las solicitudes de permiso de tu instalación. Si decides convertir una recomendación en una edición, cambia conscientemente a Agent Mode y revisa el diff antes de aprobarlo.

Punto de partida

Abre el proyecto del Lab 1

Desde la introducción, descarga y descomprime LabHandsOnBob.zip. En IBM Bob abre esta carpeta con File → Open Folder; no abras la carpeta raíz del bundle.

File → Open Folder

LabHandsOnBob/lab-1-ask-mode/
  • El explorador muestra package.json y src/ en la raíz.
  • La terminal integrada apunta a esta carpeta; no necesitas ejecutar cd.

Analiza el proyecto

Paso 1 — Confirma la carpeta

Terminal integrada

Comprueba que Bob tiene abierto el proyecto que vas a analizar.

Ejecuta en la terminal integrada

ls -la

Checkpoint

  • Ves README.md, package.json y la carpeta src/.

Paso 2 — Activa Ask Mode

IBM Bob · selector de modos

Selecciona el modo de análisis antes de enviar cualquier consulta.

  1. Abre el selector de modos junto al chat.
  2. Elige Ask.
  3. Comprueba que el nombre Ask queda visible junto al campo de entrada.

Checkpoint

  • El chat indica que Ask Mode es el modo activo.

Paso 3 — Pregunta por la arquitectura

IBM Bob · Ask Mode

Obtén un mapa de alto nivel antes de inspeccionar un archivo concreto.

Pega en el chat de Bob

Analiza la arquitectura de este proyecto de e-commerce.
Explícame:
1. Qué patrón arquitectónico se está usando.
2. Cuáles son los componentes principales.
3. Cómo fluyen los datos entre las capas.

Qué debes revisar

  • La respuesta identifica archivos o capas concretas del proyecto.
  • La explicación conecta modelos, controladores y rutas en lugar de dar una descripción genérica.

Paso 4 — Profundiza en un controlador

IBM Bob · Ask Mode

Convierte una revisión amplia en hallazgos accionables sobre autenticación y errores.

Pega en el chat de Bob

Analiza el archivo src/controllers/authController.js y explícame:
1. Qué validaciones de entrada y manejo de errores tiene.
2. Qué riesgos o buenas prácticas faltan.
3. Qué cambios priorizarías y por qué.

Qué debes revisar

  • La respuesta cita authController.js y distingue observaciones de recomendaciones.
  • Tienes una prioridad clara para discutir antes de implementar cualquier cambio.

Paso 5 — Pide documentación

IBM Bob · Ask Mode

Usa el contexto ya analizado para pedir una propuesta de documentación completa.

Pega en el chat de Bob

Propón un README.md para este proyecto que incluya:
1. Propósito y arquitectura.
2. Instrucciones de instalación.
3. Endpoints de la API con ejemplos.
4. Un diagrama de flujo de autenticación.

No modifiques archivos; muestra primero el contenido propuesto.

Checkpoint

  • El resultado cubre las cuatro secciones solicitadas.
  • Sigues en una conversación de análisis; todavía no has aprobado una edición.

Paso 6 — Haz una pregunta de seguimiento

IBM Bob · Ask Mode

Comprueba que la siguiente pregunta aprovecha el contexto de la conversación.

Pega en el chat de Bob

¿Dónde se validan los datos de entrada del usuario y qué ocurre cuando la validación falla?

Checkpoint final

  • La respuesta se apoya en el código y análisis que ya hiciste.
  • Puedes explicar cuándo usar Ask antes de cambiar a un modo de implementación.
