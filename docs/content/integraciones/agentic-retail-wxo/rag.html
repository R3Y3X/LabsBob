Paso 1 — Importar el Substitute Finder Agent

El Substitute Finder Agent no consulta inventario en tiempo real: razona sobre el catálogo interno para encontrar alternativas cuando un SKU no está disponible. Por eso no necesita el toolkit MCP, sino una base de conocimiento — que crearás en el paso siguiente.

Prompt para Bob — importar el agente de sustitutos

Sigue en la misma terminal, con el ambiente workshop activo.

Importa el segundo agente del laboratorio:

orchestrate agents import --file Substitute_Finder_Agent.yaml

Después ejecuta "orchestrate agents list" y confirma que ahora aparecen dos
agentes: SKU_Availability_Agent y Substitute_Finder_Agent.

Todavía no importes Store_Associate_Agent ni Customer_Shopping_Assistant.
Si el import falla, muéstrame el error completo y detente.
orchestrate agents import --file Substitute_Finder_Agent.yaml
orchestrate agents list
🌐 Navegador watsonx Orchestrate

Paso 2 — Crear la base de conocimiento

El archivo product-catalog.docx es el catálogo interno de la tienda. Al indexarlo como base de conocimiento, el agente puede citar atributos reales de producto en vez de inventar recomendaciones.

  1. Abre Substitute_Finder_Agent en la UI de watsonx Orchestrate.
  2. Entra a Knowledge y haz clic en Add source.
  3. Crea una base de conocimiento nueva y usa Upload files.
  4. Sube product-catalog.docx desde Lab2/confluent_agents, nómbrala enterprise_documents y espera a que termine la indexación.
  5. Haz clic en Deploy y confirma.

El nombre importa

Llámala exactamente enterprise_documents. El Customer Shopping Assistant reutilizará esta misma fuente más adelante, en vez de subir el catálogo dos veces.

🌐 Navegador watsonx Orchestrate

Paso 3 — Probar el agente en watsonx Orchestrate

La prueba real de un agente RAG no es que responda, sino que su respuesta salga del documento. Comprueba que recomienda con criterios del catálogo y que no se mete a hablar de stock — eso es trabajo de otro agente.

  1. Con Substitute_Finder_Agent abierto y desplegado, abre su chat de prueba.
  2. Envía la consulta de abajo.

Pregunta de prueba — pégala en el chat del agente

LAPTOP-DELL-XPS-15 no está disponible. Sugiere una laptop similar usando el
catálogo de productos.

Qué debes ver: una o más alternativas justificadas con atributos que están en product-catalog.docx — procesador, memoria, pantalla, rango de precio. Qué no debe pasar: el agente no debe afirmar que un producto tiene stock; no tiene forma de saberlo.

✓ Checkpoint — no avances sin esto

  • La base de conocimiento enterprise_documents aparece indexada y sin errores.
  • El agente responde con alternativas concretas del catálogo, no genéricas.
  • La respuesta no afirma disponibilidad de stock.

Criterios de éxito

Antes de pasar al supervisor, confirma que el agente razona sobre el catálogo y no sobre el conocimiento general del modelo.

  • Substitute_Finder_Agent está importado y desplegado.
  • La base de conocimiento enterprise_documents quedó indexada con product-catalog.docx.
  • Las alternativas citan atributos concretos del catálogo, no recomendaciones genéricas.
  • La respuesta no afirma disponibilidad de stock: ese dato no le corresponde a este agente.
