Lab 3 — Modo personalizado

Configura una persona de Product Manager que use un brief de producto para priorizar el siguiente paso del equipo.

1modo de proyecto
1archivo YAML resultante
1brief para probar

Qué vas a lograr

  • Crear un modo especializado desde la configuración de IBM Bob.
  • Definir rol, momento de uso, herramientas e instrucciones del Product Manager.
  • Validar el YAML de proyecto y probar una recomendación a partir de un brief real.

Qué configura un modo personalizado

↗Una persona, no una regla global

Un modo combina una identidad, instrucciones y grupos de herramientas para una tarea concreta. Las rules de tu proyecto siguen aplicando; usa rules para estándares transversales y el modo para un trabajo especializado como producto, documentación o seguridad.

El modo será de alcance Project, por lo que necesitas una carpeta abierta antes de guardarlo. Esta carpeta también contiene el brief que usarás para probar la respuesta.

Crea y prueba el Product Manager

Paso 1 — Abre Modes y crea un modo

IBM Bob · Settings · Modes

Abre el formulario donde se guarda la definición del modo.

  1. Abre el selector de modos del chat.
  2. Selecciona el engranaje de configuración.
  3. En la sección Modes, crea un modo nuevo con el botón +.

Checkpoint

  • Ves el formulario de un nuevo modo y una opción de alcance global o de proyecto.

Paso 3 — Pega las instrucciones del modo

Campo “Custom instructions”

Esto no es un prompt para enviar: pégalo en el campo de instrucciones del formulario y luego guarda el modo.

Campo: Custom instructions

1. Resume la petición en 2–3 líneas e identifica usuario, problema, resultado y restricciones.

2. Haz hasta 5 preguntas de aclaración. Si falta información, declara los supuestos.

3. Produce siempre:
   - Tarjeta MVP: objetivo, usuario, dolor, dentro y fuera de alcance.
   - Roadmap Ahora / Después / Más adelante.
   - Cinco user stories con criterios de aceptación.
   - Una métrica primaria, una o dos secundarias y un guardrail.
   - Riesgos y preguntas abiertas.

4. Haz explícitos los tradeoffs: si algo entra al MVP, otra cosa debe salir.

5. Termina con una decisión recomendada para aprobar.

6. Usa lenguaje simple y evita jerga de frameworks salvo que la pidan.

Paso 4 — Verifica el YAML de proyecto

Explorador de archivos · proyecto abierto

Comprueba que al guardar se creó la configuración del proyecto, no una definición global distinta.

Archivo: .bob/custom_modes.yaml

customModes:
  - slug: product-management
    name: product-manager
    description: Convierte ideas vagas en un plan de producto simple, priorizado y con resultados claros.
    roleDefinition: Eres un Product Manager. Ayudas a definir qué construir y por qué.
    whenToUse: Usa este modo para definir y priorizar trabajo de producto.
    customInstructions: |
      [las instrucciones que acabas de pegar]
    groups:
      - read
      - edit
      - mcp

Checkpoint

  • Existe .bob/custom_modes.yaml dentro de lab-3-modo-personalizado/.
  • El selector de modos muestra product-manager.

Paso 5 — Prueba la recomendación

IBM Bob · product-manager

Usa el brief incluido para verificar que el modo entrega artefactos de producto y no una respuesta técnica genérica.

  1. Selecciona product-manager en el chat.
  2. Envía el prompt de prueba.

Pega en el chat de Bob

Lee PRODUCT-BRIEF.md antes de responder. ¿Qué funcionalidad deberíamos construir después y cuál recomiendas para el MVP?

Checkpoint final

  • La respuesta usa el brief y explicita supuestos o preguntas pendientes.
  • Incluye una recomendación priorizada, criterios de aceptación y una decisión siguiente.
