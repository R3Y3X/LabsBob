Introducción

Antes de escribir una sola línea de código, debe comprender con qué está trabajando. En esta práctica de laboratorio, utilizará IBM Bob para explorar la aplicación SAMCO: su propósito, sus reglas comerciales y cómo encaja todo.

No escribirás ningún código. En su lugar, le hará a Bob una serie de preguntas sobre los archivos del proyecto y Bob le explicará todo en un inglés sencillo.

Obtén primero el código fuente

Todas las referencias de @SAMCO/... a continuación suponen que tiene la fuente SAMCO abierta en IBM Bob . Descarga los materiales del taller, descomprímelos y abre la carpeta antes de continuar.

Lo que lograrás

Conozca el objetivo, la lógica empresarial y el flujo de un extremo a otro de la aplicación RPG SAMCO utilizando Bob como herramienta de descubrimiento.

Caso de uso: comprender una aplicación heredada antes de modernizarla

Un error común al modernizar sistemas heredados es comenzar a codificar antes de comprender completamente lo que hace el sistema. Esta práctica de laboratorio le enseñará a utilizar Bob como herramienta de descubrimiento , una forma de construir rápidamente un modelo mental de un código base desconocido.

Paso 0: Pon a Bob en modo ask

Para esta práctica de laboratorio, Bob solo necesita leer y explicar la aplicación, no realizar ningún cambio.

Paso 1: Pregúntale a Bob sobre el objetivo general del proyecto.

Pregunta para Bob: 

        @SAMCO/QPNLSRC/SAMMNU-Main_menu_application_SAMPLE.MENUSRC
@SAMCO/QDDSSRC/ARTICLE-Article_File.PF
@SAMCO/QDDSSRC/CUSTOMER.PF
@SAMCO/QDDSSRC/ORDER.PF

Mire estos archivos y explique:
1. ¿Qué tipo de aplicación es SAMCO?
2. ¿Cuáles son las principales áreas funcionales (grupos de menús)?
3. ¿Quiénes son los principales usuarios de esta aplicación?
4. ¿Cuál es el producto final que gestiona esta aplicación final-to-end?

Mantenga la explicación simple: soy nuevo en este código base.

que buscar

  • Bob identifica SAMCO como un sistema de gestión de pedidos.
  • Bob enumera los tres grupos de menús: Archivos maestros, Informes y Utilidades.
  • Bob explica el ámbito empresarial: artículos, clientes, proveedores, pedidos.
  • Bob describe la interfaz de pantalla verde y la plataforma IBM i.

Paso 2: Pídale a Bob que le explique la lógica empresarial

2a — Artículo y normas del IVA

Pregunta para Bob: 

        @SAMCO/QDDSSRC/ARTICLE-Article_File.PF
@SAMCO/QDDSSRC/FAMILLY.PF
@SAMCO/functionsVAT/vatdef.pf
@SAMCO/functionsVAT/vat300.rpgle

Explique las reglas comerciales de los artículos:
1. ¿Qué campos tiene un artículo y qué significa cada uno?
2. ¿Cómo se agrupan los artículos en familias?
3. ¿Cómo se calcula el IVA de un artículo? Muéstrame la fórmula.
4. ¿Qué hace el campo ARDEL y por qué se utiliza en lugar de eliminar el registro?

Utilice diagramas de sirena cuando sea útil.

que buscar

  • Bob explica los campos del artículo (ID, descripción, precio de venta, precio de almacén, stock, código de IVA).
  • Bob explica la familia → código de IVA → cadena de tipos de IVA.
  • Bob muestra la fórmula del IVA: VAT = (net × rate) / 100 .
  • Bob explica el patrón de eliminación temporal ( ARDEL = 'X' ).

2b - Reglas de orden

Pregunta para Bob: 

        @SAMCO/QDDSSRC/ORDER.PF
@SAMCO/QDDSSRC/DETORD.PF
@SAMCO/QRPGLESRC/ORD100.PGM.RPGLE

Explique las reglas comerciales para los pedidos:
1. ¿Cuál es la diferencia entre un encabezado de pedido y una línea de pedido?
2. ¿Cómo se calcula el total de una línea de pedido (con y sin IVA)?
3. ¿Cuáles son los tres estados del ciclo de vida de un pedido (creado, entregado, cerrado)?
4. ¿Cómo se genera un nuevo número de pedido y por qué se utiliza el bloqueo?

Utilice diagramas de sirena cuando sea útil.

que buscar

  • Bob distingue el encabezado ORDER (cliente, fechas) de las líneas DETORD (artículo, cantidad, precio).
  • Bob muestra la fórmula del total de la línea: ODTOT = ODQTY × ODPRICE , luego ODTOTVAT = ODTOT + VAT .
  • Bob explica los tres campos de fecha: ORDATE , ORDATDEL , ORDATCLO .
  • Bob explica el patrón in *lock / out en el área de datos LASTORDNO .

2c — Reglas de clientes y proveedores

Pregunta para Bob: 

        @SAMCO/QDDSSRC/CUSTOMER.PF
@SAMCO/QDDSSRC/PROVIDER.PF
@SAMCO/common/SAMREF.PF

Explique:
1. ¿Qué información se almacena para un cliente?
2. ¿Qué es el campo CULIMCRE y cómo podría utilizarse?
3. ¿En qué se parecen en estructura los clientes y proveedores?
4. ¿Qué definiciones de campos compartidos provienen de SAMREF?

que buscar

  • Bob enumera los campos del cliente: nombre, teléfono, número de IVA, dirección, límite de crédito, fecha del último pedido.
  • Bob explica CULIMCRE como límite de crédito y CUCREDIT como saldo actual.
  • Bob observa que los clientes y proveedores comparten la misma dirección y estructura de contacto.
  • Bob explica que SAMREF es un archivo de referencia que define tipos de campos compartidos (como UNITPRICE , QUANTITY , VATCODE ).

Paso 3: Pídale a Bob que recorra el sistema de un extremo a otro

3a - El patrón de pasos del panel

Pregunta para Bob: 

        @SAMCO/QRPGLESRC/ART200-Work_with_article.PGM.SQLRPGLE

Mire el bloque select/when principal y los nombres de las subrutinas (pnl01, s01prp, s01lod, s01dsp, s01key, s01chk, s01act).

Explique:
1. ¿Cuál es el propósito de cada paso (prp, lod, dsp, key, chk, act)?
2. ¿En qué orden se ejecutan estos pasos durante una interacción normal del usuario?
3. ¿Qué sucede cuando el usuario escribe un código de opción no válido?
4. ¿Por qué se utiliza este patrón en lugar de un programa lineal simple?

Utilice diagramas de sirena cuando sea útil.

que buscar

  • Bob explica el ciclo de seis pasos: preparar → cargar → mostrar → clave → verificar → actuar.
  • Bob rastrea el flujo normal: prp borra el subarchivo, lod lo llena, dsp lo muestra, key lee las teclas de función, chk valida la entrada, act realiza la acción.
  • Bob explica que chk establece indicadores de error y vuelve a dsp en caso de una entrada no válida.
  • Bob señala que este patrón se reutiliza en todos los programas interactivos en SAMCO.

3b: creación de un pedido de un extremo a otro

Pregunta para Bob: 

        @SAMCO/QCLSRC/ORD100C2.PGM.CLLE
@SAMCO/QRPGLESRC/ORD100.PGM.RPGLE

Guíame a través del flujo completo de creación de un nuevo pedido de cliente:
1. ¿Qué hace el programa CL ORD100C2 antes de llamar a ORD100?
2. ¿Cómo selecciona el usuario un cliente?
3. ¿Cómo agrega el usuario líneas de artículo al pedido?
4. ¿Qué pasa cuando el usuario confirma el pedido (qué datos se escriben y dónde)?
5. ¿Qué se imprime al final?

Muéstrame las líneas clave de código para cada paso. Utilice diagramas de sirena cuando sea útil.

que buscar

  • Bob explica que ORD100C2 anula DETORD con un archivo de trabajo temporal, por lo que nunca se confirman datos parciales.
  • Bob muestra SltCustomer(0) para la selección de clientes y SltArticle(' ') para la selección de artículos.
  • Bob traza el cálculo de la línea: odprice = GetArtRefSalPrice(odarid) , luego odtot = odqty × odprice , luego ClcVAT .
  • Bob muestra la secuencia de confirmación: bloquear LASTORDNO , incrementar, escribir el encabezado ORDER , copiar líneas del archivo temporal a DETORD , llamar a ORD500 para imprimir.

3c - RLA frente a SQL acceso a datos

Pregunta para Bob: 

        @SAMCO/QRPGLESRC/ORD100.PGM.RPGLE
@SAMCO/QRPGLESRC/ORD200.PGM.SQLRPGLE
@SAMCO/QRPGLESRC/ART400.SQLRPGLE

Compare los dos estilos de acceso a datos utilizados en SAMCO:
1. Muéstreme un ejemplo de acceso a nivel de registro (RLA) de ORD100
2. Muéstrame el cursor SQL equivalente de ORD200
3. ¿Qué hace ART400 de manera diferente? ¿Cómo utiliza SQL para ofrecer una API REST?
4. ¿Cuáles son las ventajas prácticas de SQL sobre RLA para leer listas de datos?

que buscar

  • Bob muestra el patrón setll / read / dow not %eof RLA de ORD100 .
  • Bob muestra el patrón DECLARE CURSOR / OPEN / FETCH / CLOSE SQL de ORD200 .
  • Bob explica que ART400 usa JOIN en ARTICLE , FAMILLY y VATDEF en una consulta y devuelve una respuesta estructurada que IWS convierte a JSON.
  • Bob enumera las ventajas de SQL: menos viajes de ida y vuelta a la base de datos, compatibilidad con JOIN, optimizador SQL, más fácil de leer.

Paso 4: Pídele a Bob que resuma lo que has aprendido

Pregunta para Bob: 

        Según todo lo que hemos discutido sobre SAMCO, dame:
1. Un resumen de un párrafo de lo que hace la aplicación
2. Una lista de las 5 reglas comerciales más importantes que no debo romper al modernizarlo
3. Los 3 mayores desafíos técnicos que enfrentaré al modernizar este código base

Resumen esperado

  • Bob resume SAMCO como un sistema de gestión de pedidos de pantalla verde para artículos, clientes y pedidos.
  • Bob enumera reglas críticas: eliminaciones temporales, cálculo del IVA, bloqueo del número de pedido, ciclo de vida del pedido, fórmula del total de líneas.
  • Bob identifica los tres desafíos: RPG de formato fijo (Laboratorio 1), acceso a datos RLA (Laboratorio 3), UI de pantalla verde (Laboratorio 2).

Criterios de éxito

Ha completado con éxito esta práctica de laboratorio cuando:

  • Bob explicó el propósito y las áreas funcionales de SAMCO
  • Entiendes el patrón de eliminación temporal y por qué se utiliza
  • Puede describir la fórmula de cálculo del IVA
  • Entiendes los seis pasos de la máquina de estados de pasos del panel
  • Puede rastrear el flujo completo de creación de un pedido de cliente
  • Entiendes la diferencia entre el acceso a datos RLA y SQL

Conclusiones clave

  1. Bob es una herramienta de descubrimiento : úsala para comprender código desconocido antes de tocarlo.
  2. Deben preservarse las reglas comerciales : la modernización cambia la tecnología, no el comportamiento.
  3. Coexisten dos estilos de acceso a datos : RLA y SQL están presentes; las prácticas de laboratorio le mostrarán cómo migrar de uno a otro.
