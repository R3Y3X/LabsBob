Lab 2 — Plan y Agent

Diseña un carrito, completa los stubs del ejercicio, revisa el resultado y aplica una mejora consciente.

4cambios de modo
3archivos a completar
1revisión en Ask

Qué vas a lograr

  • Diseñar la solución antes de pedir que se modifiquen archivos.
  • Completar un modelo, un controlador y rutas que ya existen como stubs.
  • Validar la sintaxis y revisar una mejora desde Ask Mode antes de aplicarla.

Flujo de trabajo del lab

01 · Plan

Diseñar

Define estructura, rutas, riesgos y criterio de terminado.

02 · Agent

Completar

Convierte los TODOs existentes en código y revisa los cambios.

03 · Ask

Revisar

Entiende el cálculo y busca validaciones faltantes.

04 · Agent

Ajustar

Aplica solo las correcciones que hayas revisado.

Punto de partida

Abre el ejercicio de carrito

Este lab es independiente del Lab 1. Abre la carpeta del ejercicio: incluye una copia de la API y los archivos de carrito con TODOs preparados para completar.

File → Open Folder

LabHandsOnBob/lab-2-plan-agent/
  • Ves src/models/Cart.js y src/controllers/cartController.js.
  • Ambos archivos contienen comentarios TODO o respuestas 501: son stubs, no una implementación terminada.
  • src/routes/api.js ya contiene el punto donde debes completar las rutas de carrito.

Diseña, implementa y valida

Paso 1 — Diseña con Plan Mode

IBM Bob · Plan Mode

Acordar qué deben resolver los stubs antes de solicitar una implementación.

  1. Selecciona Plan en el selector de modos.
  2. Envía el siguiente prompt.

Pega en el chat de Bob

Revisa los stubs existentes de Cart, cartController y las rutas de api.

Propón un plan para completar un carrito de compras que incluya:
1. Estructura de datos e invariantes del modelo.
2. Endpoints y responsabilidades del controlador.
3. Autenticación, validación de producto, stock y límites de cantidad.
4. Casos borde y criterio de terminado.

No modifiques archivos todavía.

Qué debes revisar

  • El plan se refiere a los tres archivos existentes y no propone crear un proyecto nuevo.
  • Incluye decisiones para stock, autenticación y cantidades antes de implementar.

Paso 2 — Completa los stubs con Agent Mode

IBM Bob · Agent Mode

Convierte el plan revisado en código dentro de los archivos de este ejercicio.

  1. Cambia el selector a Agent.
  2. Revisa cada propuesta de cambio y aprueba solo lo que corresponda al plan.

Pega en el chat de Bob

Implementa el plan del carrito en los stubs existentes.

Completa únicamente:
- src/models/Cart.js
- src/controllers/cartController.js
- src/routes/api.js

Conserva el estilo del proyecto. Antes de cada edición, explica qué archivo cambiarás y por qué. Implementa autenticación, validación de producto y stock, límite de 10 unidades por producto, cálculo de total y las rutas de agregar, quitar, consultar, vaciar y actualizar cantidad.

Checkpoint

  • Los TODOs relevantes y respuestas 501 del carrito fueron reemplazados por lógica coherente.
  • Revisaste los diffs de los tres archivos antes de aprobarlos.

Paso 3 — Revisa con Ask Mode

IBM Bob · Ask Mode

Comprueba que puedes explicar el código generado antes de pedir otra modificación.

Pega en el chat de Bob

Analiza la implementación actual del carrito.

Explícame cómo se calcula el total, cómo se valida el producto y el stock, y qué riesgo queda si dos solicitudes intentan comprar el último artículo al mismo tiempo. No modifiques archivos.

Qué debes revisar

  • La respuesta relaciona sus conclusiones con el código que acabas de aprobar.
  • Distingue la validación actual de los riesgos de concurrencia que exigirían una decisión adicional.

Paso 4 — Aplica una mejora acotada

IBM Bob · Agent Mode

Usa una observación de la revisión para hacer un cambio pequeño y verificable.

Pega en el chat de Bob

Aplica únicamente estas mejoras al controlador del carrito:
- Validar que el producto existe antes de modificar el carrito.
- Rechazar cantidades mayores a 10 por producto.

Muestra el diff y espera mi aprobación antes de editar.

Checkpoint

  • El diff está limitado a la validación solicitada y conserva el comportamiento acordado.

Paso 5 — Verifica la sintaxis

Terminal integrada

Confirma que los tres archivos modificados pueden ser interpretados por Node. Este bundle no trae una suite npm test funcional, por lo que no la ejecutes como validación del lab.

Ejecuta en la terminal integrada

node --check src/models/Cart.js

Ejecuta en la terminal integrada

node --check src/controllers/cartController.js

Ejecuta en la terminal integrada

node --check src/routes/api.js

Checkpoint final

  • Los tres comandos terminan sin errores de sintaxis.
  • Puedes explicar por qué el flujo alterna entre Plan, Agent y Ask.
Si la validación no pasa

Vuelve a Ask Mode y pide que explique el error de sintaxis mostrando el archivo y la línea; luego usa Agent Mode para proponer una corrección acotada. No des por hecho que npm test es una señal válida: el script del material es un placeholder de demostración.
