SDLC Walkthrough — Plan, Code, Test, Document

Four steps covering the complete Software Development Lifecycle with Bob as your AI partner. Bob plans, implements, tests with automatic fixes, and generates a README and architecture diagram.

Step-by-Step Guide

Step 1 — Plan: Create the Architecture and Task List

Use Plan mode to give Bob your requirements. Bob will create a task list, file structure, and architecture design — without writing a single line of code yet. Review the plan carefully before approving.

Bob Prompt — Plan Mode

Create a project plan for a Python REST API that manages a todo list.
Include: architecture overview, file structure, implementation tasks,
and a list of dependencies. Use FastAPI and pytest.

Expected Output

Bob returns a structured plan: project directory tree (main.py, models.py, tests/), architecture description, and an ordered task list. No files are created yet. Review the plan and click Approve to proceed.

Step 2 — Code: Implement the Approved Plan

Switch to Agent mode. Bob will create the full project structure, install dependencies, and write all source files following best practices. Approve each file as Bob presents it.

Bob Prompt — Agent Mode

Implement the approved plan. Create the project directory structure
and all required Python files following best practices.
Install the required dependencies with pip.

Expected Output

Bob creates the project files one by one, showing each diff for approval: main.py (FastAPI app), models.py (Pydantic models), requirements.txt. Bob installs dependencies and confirms the API starts without errors.

Step 3 — Test: Write, Run, and Auto-Fix

Ask Bob to generate unit tests, run them, and automatically fix any failures. This is the build-test-diagnose-fix loop that makes Bob's SDLC integration so powerful — it iterates until all tests pass without requiring manual intervention.

Bob Prompt — Agent Mode

Create unit tests for all API endpoints using pytest.
Run the tests, fix any failures automatically, and re-run
until all tests pass. Generate a test summary report.

Expected Output

Bob creates tests/test_main.py with tests for each endpoint (GET, POST, DELETE). If any test fails, Bob reads the error, patches the code, and re-runs automatically. Final output: X passed, 0 failed in the pytest summary.

💡 Bob's Auto-Fix Pattern

If Bob finds an error, it reads the stack trace, identifies the root cause, proposes a fix, and re-runs the tests. This loop is the same pattern used in enterprise Java modernization and watsonx Orchestrate agent generation.

Step 4 — Document: README and Architecture Diagram

Ask Bob to generate project documentation including a README and a Mermaid architecture diagram. Bob generates documentation that accurately reflects what it actually built — not a generic template.

Bob Prompt — Agent Mode

Generate complete project documentation:
1. A README.md with project overview, setup instructions, and API endpoints.
2. A Mermaid architecture diagram showing the API structure and data flow.
3. A CHANGELOG.md listing all changes made in this session.

Expected Output

Bob creates README.md with setup steps and endpoint table, a Mermaid diagram embedded in the README showing FastAPI → Router → Models → DB flow, and a CHANGELOG.md. Install the Mermaid extension in Bob to view the diagram rendered inline.
