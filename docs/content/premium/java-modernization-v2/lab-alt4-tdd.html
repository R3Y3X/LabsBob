¿Qué es Test-Driven Development?

TDD es una metodología donde los tests se escriben antes que el código de implementación. El ciclo TDD sigue tres pasos:

  1. Red — escribir un test que falle y defina la funcionalidad deseada
  2. Green — escribir el código mínimo para que el test pase
  3. Refactor — mejorar el código manteniendo los tests en verde

TDD con especificaciones de API

  • Contrato claro — la especificación API define el comportamiento esperado antes de la implementación
  • Tests completos — genera suites de test completas desde la especificación
  • Guía de implementación — los tests dirigen los detalles de implementación
  • Aseguramiento de calidad — garantiza que la implementación coincide con la especificación

Ejemplo de refactor

Antes:

Date prescriptionDate = new Date();
Calendar cal = Calendar.getInstance();
cal.setTime(prescriptionDate);
cal.add(Calendar.DAY_OF_MONTH, 30);
Date expiryDate = cal.getTime();

Después:

Date prescriptionDate = new Date();
Date expiryDate = calculateExpiryDate(prescriptionDate);

private Date calculateExpiryDate(Date startDate) {
    Calendar cal = Calendar.getInstance();
    cal.setTime(startDate);
    cal.add(Calendar.DAY_OF_MONTH, 30);
    return cal.getTime();
}
