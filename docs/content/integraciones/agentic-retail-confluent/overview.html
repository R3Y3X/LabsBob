Qué vas a construir

La capa de datos operacionales en tiempo real de Voltia: tópicos de Kafka para transacciones de inventario, procesamiento con ksqlDB y cálculo automático de disponibilidad por sucursal.

Entregable del lab

  • Tópico inventory.transactions — fuente única de eventos.
  • Tópico derivado inventory.availability — disponibilidad por SKU y sucursal calculada en tiempo real.
  • 20 mensajes de ejemplo listos para que los consuman los agentes del Lab 2.

Guía rápida de identificadores visuales

  • ⬛ Terminal Acción en consola o línea de comandos local / SSH.

🌐 IBM TechZone ⚙ Config

Fase 0. Reconocer el ambiente entregado

Antes de cualquier acción, localiza la información que el instructor entregó en TechZone: la URL de acceso y las credenciales del ambiente.

  1. Ingresa a tu reserva en IBM TechZone y abre los detalles del ambiente asignado.
  2. Localiza la sección My request — encontrarás dos datos clave:
    • La IP pública de la VM (la usarás como URL base para acceder a Confluent Platform).
    • Las credenciales de acceso: usuario y contraseña del Control Center de Confluent.

✓ Checkpoint 0

  • 1 Tienes anotada la IP pública de la VM.
  • Tienes a mano SSH private key.
  • Tienes a mano el usuario y contraseña del Control Center.

Confluent Cloud — credenciales por email

El instructor enviará las credenciales de acceso a confluent.cloud directamente por correo o chat del workshop.

🌐 Confluent Platform ⚙ Config

Fase 0b. Acceder a Confluent Platform y navegar al clúster

Confluent Control Center es la UI web donde verás en tiempo real los tópicos, mensajes y schemas. Necesitas acceder antes de ejecutar cualquier script.

  1. Abre tu navegador y ve a: http://<IP_PUBLICA>
  2. Ingresa con las credenciales obtenidas en la Fase 0:
    • Username: <usuario_entregado>
    • Password: <contraseña_entregada>
  1. Una vez dentro, en el menú lateral izquierdo haz clic en Clusters → selecciona controlcenter.cluster.
  2. Verás las secciones principales: Brokers, Topics, Connect, ksqlDB. Deja esta pestaña abierta — la usarás para verificar cada paso.

✓ Checkpoint 0b

  • Estás dentro de Confluent Control Center y puedes ver el menú del clúster.
  • La sección Topics es visible en el menú lateral.

Confluent Cloud — navegación al clúster

  1. Inicia sesión en confluent.cloud.
  2. En el menú superior selecciona el Environment y luego el Cluster indicado por el instructor.

Prerrequisitos

Abre Bob en Agent Mode, reemplaza los 3 valores marcados y pega el prompt. Bob crea la clave SSH, verifica la conexión, genera el .env completo y deja el entorno listo para los labs.

⚙ Config Reemplaza estos 3 valores antes de copiar

  • [IP_PUBLICA_VM] — IP pública de tu VM en TechZone (ej. 163.66.95.196).
  • [PASSWORD_ADMIN] — contraseña del usuario admin (aparece en los outputs de TechZone).
  • [PASSWORD_KAFKA_ADMIN] — contraseña del usuario kafka-admin (aparece en los outputs de TechZone).
  • [PEGA_AQUI_CLAVE_PRIVADA_PEM] — contenido completo de tu archivo .pem, incluyendo las líneas -----BEGIN----- y -----END-----.
🤖 Prompt para Bob — SSH + .env completo
Hola Bob, serás mi asistente de infraestructura para este workshop de Event Streaming. Aquí tienes mis accesos y parámetros: - IP del Host: [IP_PUBLICA_VM] - Usuario SSH: root - Contenido de la Clave Privada (guardar como cflt-vsi-key.pem): -----BEGIN OPENSSH PRIVATE KEY----- [PEGA_AQUI_CLAVE_PRIVADA_PEM] -----END OPENSSH PRIVATE KEY----- Instrucciones para ti: 1. Crea el archivo 'Lab1/inventory-pipeline/cflt-vsi-key.pem' con la clave provista. 2. Aplica `chmod 600 Lab1/inventory-pipeline/cflt-vsi-key.pem`. 3. Verifica la conexión SSH: ssh -i Lab1/inventory-pipeline/cflt-vsi-key.pem root@[IP_PUBLICA_VM] 'echo ok' 4. Crea el archivo 'Lab1/inventory-pipeline/.env' con exactamente este contenido: SSH_HOST=root@[IP_PUBLICA_VM] SSH_KEY=Lab1/inventory-pipeline/cflt-vsi-key.pem BOOTSTRAP_SERVERS=[IP_PUBLICA_VM]:9094,[IP_PUBLICA_VM]:9095,[IP_PUBLICA_VM]:9096 KAFKA_SASL_USERNAME=kafka-admin KAFKA_SASL_PASSWORD=[PASSWORD_KAFKA_ADMIN] KAFKA_SECURITY_PROTOCOL=SASL_SSL KAFKA_SASL_MECHANISM=PLAIN KSQLDB_ENDPOINT_EXTERNAL=https://[IP_PUBLICA_VM]/ksqldb KSQLDB_USERNAME=admin KSQLDB_PASSWORD=[PASSWORD_ADMIN] SCHEMA_REGISTRY_URL=https://[IP_PUBLICA_VM]/sr SCHEMA_REGISTRY_USER=admin SCHEMA_REGISTRY_PASSWORD=[PASSWORD_ADMIN] 5. Confirma con "listo" cuando la conexión SSH funcione y el .env esté creado.

✓ Checkpoint

  • Bob responde "listo" — SSH activo, cflt-vsi-key.pem con permisos 600 y .env generado.
  • No avances al Lab 1 hasta ver esta confirmación — el setup.sh la necesita para funcionar.

⚙ Config Antes de empezar — Confluent Cloud + .env

  1. Recibe de tu instructor el archivo .env con BOOTSTRAP_SERVERS, KAFKA_API_KEY y KAFKA_API_SECRET.
  2. Cópialo a la raíz de Labs-tech-summit/.
  3. Inicia sesión en confluent.cloud y selecciona el cluster que indicó el instructor.
