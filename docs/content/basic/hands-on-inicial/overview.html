Prepara el recorrido

  • IBM Bob IDE con acceso a Ask, Plan y Agent.
  • Node.js 18+ para el Lab 2 y el servidor MCP del Lab 4.
  • Una API key de Tavily para el Lab 4; créala solo cuando llegues a ese lab.

Tu recorrido de cuatro labs

Cada etapa es independiente. El orden recomendado construye una historia clara: entender, diseñar e implementar, especializar y conectar.

01 · IBM Bob · Ask

Entender un proyecto

Analiza la arquitectura y genera documentación sin modificar la aplicación.

lab-1-ask-mode/ → explicación y README propuesto.

02 · Plan → Agent → Ask

Diseñar y completar un carrito

Transforma stubs con TODOs en una implementación revisada.

lab-2-plan-agent/ → modelo, controlador y rutas.

03 · Configuración de proyecto

Crear un Product Manager

Define un modo especializado que convierte un brief en decisiones de producto.

lab-3-modo-personalizado/ → .bob/custom_modes.yaml.

04 · IBM Bob · MCP

Consultar la web con Tavily

Configura un servidor MCP de proyecto y valida que Bob usa fuentes actuales.

lab-4-mcp-tavily/ → Tavily activo y una respuesta citada.

Elige el modo según la tarea

?

Ask Mode

Entender y explicar

Úsalo para explorar código, pedir explicaciones y documentar lo que encuentres sin hacer cambios de implementación.

↗

Plan Mode

Diseñar antes de actuar

Úsalo para convertir requisitos en un plan, alternativas, riesgos y criterios de aceptación que puedas revisar.

</>

Agent Mode

Implementar y validar

Úsalo cuando necesites modificar archivos, ejecutar comandos o utilizar herramientas MCP con las aprobaciones configuradas.

Cómo leer los pasos

Todos los labs usan la misma secuencia: el contexto te dice dónde actuar; el propósito explica para qué; el bloque copiable contiene solo lo que debes pegar o ejecutar; el checkpoint confirma que puedes continuar.

Las capturas son una referencia

  • Los nombres de los menús, rutas y paneles pueden variar entre versiones de IBM Bob.
  • Las respuestas generadas por IA no serán idénticas a las capturas; valida los criterios del paso, no el texto exacto.

Soporte

Si un checkpoint no coincide con lo que ves, conserva el mensaje o captura relevante y consulta al equipo facilitador antes de pasar al siguiente lab.
