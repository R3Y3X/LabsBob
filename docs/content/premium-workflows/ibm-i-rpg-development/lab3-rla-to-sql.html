Caso de uso: convertir la búsqueda de artículos de RLA a SQL

Convertiremos la operación de búsqueda de artículos ( CHAIN ) utilizada al editar un artículo para usar SQL en su lugar.

Paso 1: Pídale a Bob que le explique la operación RLA

Pregunta para Bob:

Explique en términos simples:

que buscar

Paso 3: Pídele a Bob que agregue datos relacionados

Pregunta para Bob: 

        Mejore SQL para obtener también la descripción de la familia en una consulta.

El código original hace esto por separado:
- Línea 249: cadena y artículo1;
- Línea 250: famdesc = getArtFamDesc(artifa);

Muéstreme cómo obtener datos del artículo y de la familia en una declaración SQL usando JOIN.

La respuesta de Bob (ilustrativa)

          Ejecutivo SQL
  SELECCIONE A.ARID, A.ARDESC, A.ARSALEPR, A.ARWHSPR,
         A.ARTIFA, A.ARSTOCK, A.ARMINQTY, A.ARVATCD,
         F.FADESC
  EN :article.arid, :article.ardesc, :article.arsalepr,
       :article.arwhspr, :article.artifa, :article.arstock,
       :article.arminqty, :article.arvatcd,
       :familiaDesc
  DEL ARTÍCULO A
  IZQUIERDA UNIRSE A LA FAMILIA F EN A.ARTIFA = F.FAID
  DONDE A.ARID = :árido;

Paso 4: Pregúntale a Bob sobre los beneficios

Pregunta para Bob: 

        ¿Cuáles son los beneficios de usar SQL en lugar de RLA para esta operación?
Enumere 2-3 beneficios simples.

Beneficios esperados

  1. Un viaje a la base de datos : JOIN obtiene datos relacionados en una consulta.
  2. Más flexible : fácil de agregar más campos o condiciones.
  3. Mejor rendimiento : el optimizador SQL puede elegir la mejor ruta de acceso.

Criterios de éxito

Ha completado con éxito esta práctica de laboratorio cuando:

  • Entiendes lo que hace CHAIN
  • Verá el equivalente SQL
  • Entiendes cómo JOIN mejora el código
  • Sabes por qué SQL es mejor que RLA

Comparación antes y después

Antes (RLA - 2 operaciones)

        // Operación 1: Obtener artículo
cadena árida artículo1;

// Operación 2: Obtener descripción familiar
famdesc = getArtFamDesc(artifa);

Después (SQL - 1 operación)

        // Obtener ambos en una sola consulta
Ejecutivo SQL
  SELECCIONE A.*, F.FADESC
  EN :artículo, :familyDesc
  DEL ARTÍCULO A
  IZQUIERDA UNIRSE A LA FAMILIA F EN A.ARTIFA = F.FAID
  DONDE A.ARID = :árido;

Resultado : menos operaciones de base de datos, código más limpio.

Conclusiones clave

  1. SQL es más potente : puede obtener datos relacionados en una consulta.
  2. Bob puede convertir : pídele a Bob que convierta RLA a SQL.
  3. Los JOIN son útiles : combinan datos de varias tablas.
  4. Comience poco a poco : convierta una operación a la vez.

Ejemplo del mundo real

Este patrón se utiliza en SAMCO/QRPGLESRC/ART400.SQLRPGLE (líneas 79-97): 

        Ejecutivo SQL
  DECLARAR EL CURSOR C1 PARA
  SELECCIONAR
    A.ARID, A.ARDESC, A.ARTIFA,
    FUSIONAR(F.FADESC, ''),
    A.ARVATCD,
    FUSIONAR(V.VATRATE, 0),
    A.ARSALEPR, A.ARWHSPR, A.ARSTOCK, A.ARMINQTY, A.ARDEL
  DEL ARTÍCULO A
  IZQUIERDA UNIRSE A LA FAMILIA F EN A.ARTIFA = F.FAID
  IZQUIERDA UNIRSE A VATDEF V EN A.ARVATCD = V.VATCODE
  DONDE A.ARDEL = ' '
  PEDIR POR A.ARID;

¡Esto obtiene artículo + familia + datos de IVA en UNA consulta!
