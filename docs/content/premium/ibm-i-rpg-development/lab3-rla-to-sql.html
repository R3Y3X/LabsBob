Paso 1 — Explica la operación RLA

@SAMCO/QRPGLESRC/ART200-Work_with_article.PGM.SQLRPGLE

Mira la línea 249: chain arid article1;

Explica en términos simples:
1. ¿Qué hace CHAIN?
2. ¿Qué datos recupera?
3. ¿Qué pasa si no encuentra el registro?

Qué buscar

  • CHAIN lee un registro por clave
  • Carga datos en el formato de registro FARTI
  • Si no encuentra, %FOUND() es falso

Paso 2 — Equivalente SQL

Convierte esta operación RLA a SQL:

chain arid article1;

Requisitos:
- Usar sentencia SQL SELECT
- Obtener los mismos campos
- Manejar el caso "no encontrado"
- Mantenerlo simple
- Muéstrame el código SQL

Respuesta ilustrativa

// Forma RLA antigua:
chain arid article1;

// Forma SQL nueva:
Exec SQL
  SELECT ARID, ARDESC, ARSALEPR, ARWHSPR, ARTIFA,
         ARSTOCK, ARMINQTY, ARVATCD
  INTO :article.arid, :article.ardesc, :article.arsalepr,
       :article.arwhspr, :article.artifa, :article.arstock,
       :article.arminqty, :article.arvatcd
  FROM ARTICLE
  WHERE ARID = :arid;

If SQLCODE = 0;
  // Registro encontrado
Else;
  // No encontrado
EndIf;

Paso 3 — Añade datos relacionados con JOIN

Mejora el SQL para obtener también la descripción de familia en una sola consulta.

El código original hace esto por separado:
- Línea 249: chain arid article1;
- Línea 250: famdesc = getArtFamDesc(artifa);

Muéstrame cómo obtener artículo y familia en una sentencia SQL con JOIN.
Exec SQL
  SELECT A.ARID, A.ARDESC, A.ARSALEPR, A.ARWHSPR,
         A.ARTIFA, A.ARSTOCK, A.ARMINQTY, A.ARVATCD,
         F.FADESC
  INTO :article.arid, :article.ardesc, :article.arsalepr,
       :article.arwhspr, :article.artifa, :article.arstock,
       :article.arminqty, :article.arvatcd,
       :familyDesc
  FROM ARTICLE A
  LEFT JOIN FAMILLY F ON A.ARTIFA = F.FAID
  WHERE A.ARID = :arid;

Paso 4 — Beneficios

¿Cuáles son los beneficios de usar SQL en lugar de RLA para esta operación?
Lista 2-3 beneficios simples.
  • Un solo viaje a la base de datos con JOIN
  • Más flexible para añadir campos o condiciones
  • Mejor rendimiento: el optimizador SQL elige el mejor acceso
