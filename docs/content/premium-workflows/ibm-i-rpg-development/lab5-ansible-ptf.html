Laboratorio 5 — Gestión de PTF con Ansible (opcional)

Crea un asistente Ansible para comprobar, informar y automatizar la gestión de PTF en IBM i.

Requiere IBM i aprovisionado
~30 minutos
5–10 BobCoins estimados
Premium acceso requerido

Introducción

Dificultad: Intermedio

Esta práctica de laboratorio lo guiará a través de la creación de un asistente automatizado para administrar las correcciones temporales del programa (PTF) en sistemas IBM i utilizando Ansible con la integración del asistente Bob AI. Aprenderá a aprovechar las capacidades de inteligencia artificial de Bob para optimizar las comprobaciones de moneda PTF, automatizar los informes de cumplimiento y administrar las actualizaciones del sistema de manera eficiente.

Objetivos

  • Configure Bob con Ansible especializado para conocimientos de IBM i.
  • Cree guías para consultar e informar el estado de PTF.
  • Automatice la verificación de cumplimiento de moneda PTF.
  • Genere informes formateados para administradores de sistemas.
  • Explore escenarios de automatización avanzada para entornos IBM i.

Laboratorio opcional: requiere un entorno aprovisionado

Este laboratorio es opcional . Requiere un entorno IBM i aprovisionado (acceso SSH, autoridades de gestión PTF) y el servidor IBM i MCP de Lab 4 . Si no tiene uno, puede omitir esta práctica de laboratorio de manera segura.

Requisitos previos

Requisitos del sistema IBM i

  • IBM i 7.3 o superior.
  • Demonio SSH ejecutándose ( STRTCPSVR SERVER(*SSHD) ).
  • Perfil de usuario con *ALLOBJ o autoridades de gestión PTF apropiadas.
  • Python 3.6+ instalado a través de yum ( yum install python3 ).
  • Gestión de paquetes de código abierto de IBM i configurada.

Requisitos de la estación de trabajo Bob

  • Ansible 2.9+ instalado ( pip install ansible ).
  • Python 3.8+ con pip.
  • Colecciones de IBM i Ansible:

$ Terminal integrada

        ansible-galaxy collection install ibm.power_ibmi

$ Terminal integrada

        ansible-galaxy collection install ibm.power_hmc
  • Autenticación basada en claves SSH configurada para el sistema IBM i (instrucciones incluidas en la guía de laboratorio).
  • Asistente Bob AI instalado y configurado.
  • Conectividad de red al sistema IBM i (puerto 22): consulte Lab 4.

Configuración del modo personalizado

Para esto usaremos el modo personalizado ansible-for-i definido en ./.bob/custom_modes.yaml :

Archivo de configuración · YAML

        - slug: ansible-for-i
  name: ℹ️ Ansible for i
  whenToUse: an agent who specializes IBM i with Ansible
  roleDefinition: |
    You are an expert in IBM i system administration and Ansible automation.
    Focus on:
    - IBM i-specific Ansible modules (ibm.power_ibmi collection)
    - PTF management and system currency
    - YAML playbook best practices
    - IBM i object authorities and security
    - Power Systems hardware management
    - High availability configurations

    commands:
      - ansible-playbook
      - ansible-inventory
      - ansible-doc

    knowledge_areas:
      - IBM i operating system concepts
      - PTF lifecycle and management
      - Ansible playbook development
      - Jinja2 templating
      - IBM i Ansible modules: ibmi_fix, ibmi_sql_query, ibmi_object_authority
      - Power HMC integration
      - PowerHA SystemMirror automation
  groups:
    - read
    - edit
    - mcp
    - command

Primera creación del libro de jugadas

Parte 1: Usar a Bob para generar el libro de jugadas

Usemos a Bob para generar la estructura completa del libro de jugadas y el código de automatización.

Paso 1: activa el modo

  • Expanda el menú desplegable de modos debajo de la entrada del chat.
  • Seleccione ℹ️ Ansible for i .

Paso 2: pídale a Bob que cree la automatización de verificación de moneda PTF

Pega en el chat de Bob

        Cree un proyecto de automatización Ansible para la gestión de IBM i PTF con lo siguiente:

1. Estructura de directorios: /ansible con subdirectorios para inventories/development, guías y plantillas
2. Un libro de jugadas llamado check_ptf_currency.yml que:
   - Consulta información del sistema IBM i usando ibmi_sql_query
   - Comprueba los niveles del grupo PTF (SF99740, SF99738) usando ibmi_fix_group_check
   - Listas instaladas PTFs desde QSYS2.PTF_INFO
   - Se compara con los PTF críticos faltantes
   - Calcula estadísticas de cumplimiento.
   - Genera un informe HTML usando una plantilla Jinja2, guárdelo en ./ansible/reports
3. Un archivo de inventario para el entorno de desarrollo con el grupo ibmi_systems
4. Una plantilla de Jinja2 para el informe de moneda PTF con información del sistema, estado del grupo PTF, PTF faltantes y métricas de cumplimiento
5. Notas útiles
  - Utilice el servidor IBM i MCP para
    - comprobar qué columnas están realmente disponibles en SYSTEM_STATUS_INFO
    - verifique la estructura real de la tabla PTF_INFO para ver qué columnas están disponibles
  - Columnas OS_VERSION y OS_RELEASE que no existen

Utilice los módulos de colección IBM i Ansible (ibm.power_ibmi) y siga las mejores prácticas.

Paso 3: revisar los archivos generados por Bob

Bob creará:

  • /ansible/inventories/development/hosts.yml — Configuración de inventario.
  • /ansible/playbooks/check_ptf_currency.yml — Libro de jugadas principal.
  • /ansible/templates/ptf_currency_report.j2 — Plantilla de informe.

Parte 2: Comprender el libro de jugadas generado

Después de que Bob genere la automatización, revise la estructura del libro de jugadas de cheques de moneda PTF en /ansible/playbooks/check_ptf_currency.yml . Debería verse algo como:

Archivo de configuración · YAML

        ---
- name: Check PTF Currency on IBM i Systems
  hosts: ibmi_systems
  gather_facts: no

  vars:
    report_path: "/tmp/ptf_currency_report_{{ ansible_date_time.date }}.html"

  tasks:
    - name: Gather system information
      ibm.power_ibmi.ibmi_sql_query:
        sql: "SELECT * FROM SYSIBMADM.ENV_SYS_INFO"
      register: system_info

    - name: Get current PTF group level
      ibm.power_ibmi.ibmi_fix_group_check:
        groups:
          - "SF99740"  # Technology Refresh group
          - "SF99738"  # Cumulative PTF package
      register: ptf_groups

    ...

Es posible que Bob necesite repetir el libro de jugadas varias veces para adaptarse a su sistema actual.

Salida de la revisión:

  • Marque PLAY RECAP para ver el estado de éxito/fracaso.
  • Examine el resultado de la tarea para obtener detalles de PTF.
  • Abra el informe HTML generado en el navegador.
  • Revise los PTF faltantes y el porcentaje de cumplimiento.

Solución de problemas comunes:

  • Fallos de autenticación SSH: verifique la configuración de autenticación basada en claves.
  • Módulo no encontrado: reinstale la colección ibm.power_ibmi .
  • Permiso denegado: verifique las autoridades de usuario en IBM i.
  • Tiempo de espera de conexión: verifique las reglas del firewall y la conectividad de la red.

Cuando finalice el libro de jugadas, verifique el resultado abriendo el archivo HTML en el navegador.

$ Terminal integrada

        open ./ansible/reports/<REPORT_NAME>

Algunos casos de uso adicionales

1. Aplicación automatizada PTF

Archivo de configuración · YAML

        - name: Apply PTF package
  ibm.power_ibmi.ibmi_fix:
    product_id: "5770SS1"
    fix_list: ["SI12345", "SI67890"]
    operation: "apply"

2. Monitoreo del estado del sistema

Archivo de configuración · YAML

        - name: Monitor system resources
  ibm.power_ibmi.ibmi_sql_query:
    sql: "SELECT * FROM QSYS2.SYSTEM_STATUS_INFO"
  register: health_metrics

3. Automatización de copias de seguridad

Archivo de configuración · YAML

        - name: Save system configuration
  ibm.power_ibmi.ibmi_save:
    objects: ["*ALL"]
    savefile: "QGPL/SYSBACKUP"
    parameters: "UPDHST(*YES)"

4. Gestión de autoridad de usuario

Archivo de configuración · YAML

        - name: Grant object authority
  ibm.power_ibmi.ibmi_object_authority:
    object_name: "MYLIB/MYFILE"
    user: "APPUSER"
    authority: "*CHANGE"

5. Monitoreo del desempeño

Archivo de configuración · YAML

        - name: Collect performance data
  ibm.power_ibmi.ibmi_sql_query:
    sql: "SELECT * FROM QSYS2.SYSTEM_ACTIVITY_INFO"

6. Orquestación de PowerHA

Archivo de configuración · YAML

        - name: Check cluster status
  ibm.power_ibmi.ibmi_cl_command:
    cmd: "DSPCLU CLUSTER(MYCLUSTER)"
  register: cluster_status

7. Integración de potencia HMC

Archivo de configuración · YAML

        - name: Provision LPAR
  ibm.power_hmc.lpar:
    hmc_host: "hmc.example.com"
    system_name: "POWER9-SYS"
    name: "NEW_LPAR"
    state: "present"

8. Instalación de software

Archivo de configuración · YAML

        - name: Install licensed program
  ibm.power_ibmi.ibmi_install_product:
    product: "5770DG1"
    option: "*BASE"

9. Auditoría de seguridad

Archivo de configuración · YAML

        - name: Audit user profiles
  ibm.power_ibmi.ibmi_sql_query:
    sql: "SELECT * FROM QSYS2.USER_INFO WHERE STATUS = '*ENABLED'"

10. Integración de ServiceNow

Archivo de configuración · YAML

        - name: Create change request
  servicenow.itsm.change_request:
    instance: "{{ snow_instance }}"
    short_description: "PTF Application - {{ ansible_date_time.date }}"
    description: "Applying PTFs: {{ missing_ptfs.missing_fixes | join(', ') }}"
    state: "new"
