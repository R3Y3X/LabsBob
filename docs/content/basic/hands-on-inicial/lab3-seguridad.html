LAB 3 — IBM Bob el Guardián: Seguridad

IBM Bob tiene capacidades integradas de análisis de seguridad que detectan vulnerabilidades automáticamente mientras escribes código. Es como tener un experto en seguridad revisando tu código en tiempo real — sin instalar plugins ni herramientas adicionales.

Objetivos de Aprendizaje

  • ✅ Usar IBM Bob para detectar vulnerabilidades automáticamente
  • ✅ Entender los iconos de seguridad que IBM Bob muestra en el código
  • ✅ Obtener sugerencias de remediación con código corregido
  • ✅ Generar un reporte de seguridad profesional

Los Iconos de IBM Bob

IBM Bob muestra 2 tipos de iconos a la izquierda del código:

Casco de IBM Bob

Sugerencia o acción de IBM Bob — aparece en code review, bugs detectados y mejoras de código

Escudo de Seguridad

Vulnerabilidad de seguridad detectada — aparece en security scan y problemas de seguridad

¿Qué Detecta IBM Bob Automáticamente?

  • 🔴 Vulnerabilidades críticas: Hardcoded secrets, SQL injection, code injection
  • 🟡 Problemas de seguridad: Falta de validación, exposición de datos sensibles
  • 🟠 Malas prácticas: Passwords sin hash, tokens sin expiración
  • 🔵 Mejoras recomendadas: Soft deletes, rate limiting, logging seguro

Ejercicio: Auditoría de Seguridad

Paso 1 — Activar Ask Mode

Haz clic en el selector de modos → selecciona Ask Mode. Verifica en la barra de estado: Ask activo.

¿Por qué Ask Mode para el análisis?

Ask Mode lee el código sin modificarlo y tiene 270k tokens de contexto — ideal para un análisis exhaustivo de todo el archivo vulnerable de una sola vez.

Paso 2 — Analizar Código Vulnerable

Abre el archivo lab-3-seguridad/codigo-vulnerable/authController-vulnerable.js y observa los comentarios VULNERABILIDAD #X que marcan los problemas. Luego envía este prompt a IBM Bob:

Analiza el archivo lab-3-seguridad/codigo-vulnerable/authController-vulnerable.js

Identifica todas las vulnerabilidades de seguridad y proporciona:
1. Nombre y número de cada vulnerabilidad
2. Nivel de severidad (CRÍTICA, ALTA, MEDIA, BAJA)
3. Descripción del problema
4. Impacto potencial
5. Código corregido

Organiza por severidad.

✅ Salida Esperada

IBM Bob identificará las 15+ vulnerabilidades organizadas por severidad crítica → alta → media → baja, con código corregido para cada una. El proceso completo toma menos de 60 segundos.

Paso 3 — Aplicar Correcciones con Agent Mode

Con el análisis completo, cambia a Agent Mode para aplicar las correcciones:

Basándote en el análisis anterior, aplica todas las correcciones
de seguridad en authController-vulnerable.js.

Prioriza las vulnerabilidades CRÍTICAS y ALTAS primero.
Muéstrame cada cambio antes de aplicarlo.

⚠️ Agent Mode requiere aprobación para escrituras

Cada modificación al archivo requerirá tu confirmación — esto es el comportamiento correcto y seguro de IBM Bob 2.1.

Mejores Prácticas de Seguridad

✅ SÍ hacer

  • Analiza con IBM Bob antes de cada commit
  • Valida TODOS los inputs del usuario
  • Usa variables de entorno para secrets
  • Implementa rate limiting
  • Hash passwords con bcrypt
  • Usa JWT con expiración

❌ NO hacer

  • Hardcodear secrets en el código
  • Exponer errores internos al cliente
  • Confiar en datos del cliente sin validar
  • Ignorar los iconos de escudo de IBM Bob
  • Almacenar passwords en texto plano
  • Loguear datos sensibles (passwords, tokens)
