Un compile verde no es toda la historia

mvn clean compile confirma que la actualización Java y el rename de namespace son internamente consistentes. La configuración de runtime de Liberty (server.xml, context root, DTD de Struts) es una capa aparte que solo aparece si arrancas el servidor.

Solución de problemas y ayuda

Solución de problemas

Trabaja estos puntos en orden — se apilan y cada uno puede enmascarar los de abajo:

  1. Un Liberty obsoleto ocupa el puerto → cada fix parece no hacer nada
  2. Liberty arrancó con cero features (CWWKF0001E) → nada escucha en el puerto
  3. server.xml aún tiene features Java EE → Context Root Not Found
  4. struts.xml apunta a un DTD inexistente → el filtro Struts falla al cargar

CWWKF0001E — feature definition not found for servlet-6.0

El servidor "arranca" pero la lista de features está vacía. El Liberty descargado es un kernel sin servlet-6.0/pages-3.1.

El pom.xml enviado fija un runtime completo bajo liberty-maven-plugin (openliberty-runtime:26.0.0.5). Si Bob reescribió el bloque del plugin, restáuralo o ejecuta:

mvn liberty:install-feature
mvn liberty:run

Context Root Not Found en el navegador

1. URL incorrecta. Bob suele fijar context-root="/simple-pharmacy"; la URL del Lab 1 (/simple-pharmacy.war/dashboard) ya no funciona. Toma la URL del log de arranque:

grep CWWKT0016I target/liberty/wlp/usr/servers/defaultServer/logs/messages.log

2. Servidor obsoleto. Si ves CWWKO0221E (puerto 9081 en uso), mata el proceso anterior:

lsof -ti:9081,9443 | xargs kill -9

3. La app no arrancó. Busca CWWKZ0002E — ver entrada siguiente.

CWWKC2263E — Servlet 6.0 vs 3.1 (el fallo más común)

Bob migró la app a Jakarta EE 10 pero dejó server.xml en el feature set Java EE antiguo. web.xml declara Servlet 6.0; server.xml aún provisiona Servlet 3.1.

Pega la línea CWWKC2263E en el chat de Bob, o reemplaza el bloque <featureManager> manualmente:

<featureManager>
    <feature>webProfile-10.0</feature>
</featureManager>

Elimina mpMetrics-1.1 si está — depende de servlet-3.1 y bloquea servlet-6.0. jdbc-4.1 también puede ir; la app usa repositorios en memoria.

Filtro Struts: FileNotFoundException: struts-7.0.dtd

Bob apuntó struts.xml a un DTD que no existe. Apache nunca publicó struts-7.0.dtd; struts2-core solo incluye DTDs hasta 6.5.

Abre src/main/resources/struts.xml y fija el DOCTYPE a una versión que exista:

<!DOCTYPE struts PUBLIC
    "-//Apache Software Foundation//DTD Struts Configuration 2.5//EN"
    "http://struts.apache.org/dtds/struts-2.5.dtd">

Struts 7 lo lee sin problema. Un compile verde no detecta esto — solo aparece al arrancar el servidor.

Otros problemas frecuentes

  • JSPG0303W / JSTL javax: warnings inofensivos — ningún JSP usa JSTL. Elimina javax.servlet:jstl del pom o ignóralo.
  • Terminal de Bob sigue en Java 8: abre terminal nueva o sdk use java 21.0.7-zulu.
  • Bob no lee archivos: verifica que abriste snapB-java-upgrade/ como raíz, no la carpeta padre.
  • cannot find symbol ActionSupport: pide a Bob: «Busca imports restantes de com.opensymphony.xwork2 y actualízalos a org.apache.struts2.»
  • Referencias javax.servlet.* en runtime: pide a Bob: «Audita todos los imports javax.* que deban ser jakarta.*.»
  • Errores tras las recetas: esperados — pega el output completo y pide a Bob que investigue.
