Los 3 Modos de IBM Bob — Tu Equipo de Expertos

Imagina que IBM Bob es como tener 3 expertos diferentes en tu equipo, cada uno especializado en un tipo de tarea:

Ask Mode — El Consultor

Responder preguntas y explicar código sin modificarlo. Ideal para entender código legacy, revisar lógica de negocio o buscar explicaciones.

Herramientas: lectura auto-aprobada de archivos, análisis de código

Plan Mode — El Arquitecto

Diseñar soluciones antes de implementarlas. Crea diagramas, analiza requisitos, propone alternativas considerando seguridad y escalabilidad.

Herramientas: diagramas Mermaid, análisis de requisitos, sin edición

Agent Mode — El Implementador

Escribir, modificar y refactorizar código, más herramientas externas: MCP, Browser, Skills. Puede lanzar subagentes para tareas aisladas y ejecutar en paralelo.

Herramientas: leer/escribir archivos, comandos, MCP, Browser, Skills, subagentes

Regla de Oro

Cambia de modo según lo que necesites hacer. No uses un solo modo para todo. Puedes cambiar de modo en cualquier momento, incluso a mitad de una tarea.

Ejercicio: Sistema de Carrito de Compras

Vamos a implementar un carrito de compras usando 3 modos diferentes para cada fase del desarrollo.

Paso 1 — Plan Mode: Diseñar la Solución

Primero usa Plan Mode para diseñar la arquitectura — sin escribir código.

  1. Abre el selector de modos → elige Plan
  2. Envía el prompt de diseño del carrito

Una vez en Plan Mode, envía este prompt:

Necesito diseñar un sistema de carrito de compras para nuestra API de e-commerce.

Requisitos:
- Los usuarios deben poder agregar/eliminar productos
- Calcular el total con descuentos
- Persistir el carrito en la base de datos
- Validar stock antes de agregar

Por favor, diseña:
1. La estructura de datos del carrito
2. Los endpoints necesarios
3. El flujo de datos
4. Consideraciones de seguridad
5. Un diagrama de arquitectura

Qué debes ver

  • Diseño sin archivos creados aún
  • Diagramas Mermaid y alternativas

Paso 2 — Agent Mode: Implementar la Solución

Con el plan listo, cambia al selector de modos → elige Agent.

Envía un solo prompt — Bob decide qué construir en paralelo y en qué orden:

Basándote en el plan del carrito de compras que acabamos de diseñar, implementa el sistema completo:

1. Modelo Cart en src/models/Cart.js
   - Referencia al usuario
   - Array de items (producto, cantidad, precio al momento de agregar)
   - Métodos para calcular el total
   - Validación de stock
   - Timestamps

2. Controlador CartController en src/controllers/cartController.js
   - addToCart: Agregar producto al carrito
   - removeFromCart: Eliminar producto del carrito
   - getCart: Obtener carrito del usuario
   - clearCart: Vaciar el carrito
   - updateQuantity: Actualizar cantidad de un producto

3. Rutas en src/routes/api.js
   POST   /api/cart/add
   DELETE /api/cart/remove/:productId
   GET    /api/cart
   DELETE /api/cart/clear
   PUT    /api/cart/update/:productId
   Todas las rutas deben requerir autenticación.

Aquí se ve el poder de Agent Mode

Bob analiza las dependencias entre archivos, decide qué puede crear en paralelo y qué debe ir en orden, y ejecuta todo de forma asíncrona. Revisa cada diff antes de confirmar — las escrituras siempre requieren aprobación explícita.

Paso 3 — Ask Mode: Entender y Mejorar el Código

Con el código implementado, cambia al selector de modos → elige Ask para analizar sin modificar nada.

Envía este prompt para analizar el código recién implementado:

Explícame cómo funciona el método calculateTotal() en el modelo Cart.

¿Qué validaciones de seguridad tiene el controlador addToCart?

¿Cómo se maneja la concurrencia cuando dos usuarios intentan
comprar el último producto en stock?

Respuesta esperada de IBM Bob

El método calculateTotal() debería:

  1. Iterar sobre cada ítem del carrito.
  2. Multiplicar cantidad por precio.
  3. Aplicar descuentos cuando corresponda.
  4. Sumar el total final.

En addToCart, verifica:

  • La autenticación del usuario.
  • La validez del productId.
  • La disponibilidad de stock.
  • Que el producto exista.
  • Un límite de cantidad por producto.

Vuelve a Agent Mode y aplica las mejoras sugeridas:

Basándote en el análisis de Ask Mode, agrega las validaciones
faltantes en el controlador addToCart:
- Validar que el producto existe
- Limitar cantidad máxima a 10 unidades por producto
