Parte 6 — Animaciones

Tu tienda funciona y ya tiene su asistente. Ahora vas a usar Framer Motion (ya instalado) para que se sienta pulida: una grilla que entra escalonada, un toast con rebote, el badge del carrito que "salta" y una confirmación de reserva satisfactoria.

Antes de empezar

Vas a editar algunos archivos que estaban "hechos" (ToastContext.jsx, Header.jsx) — es lo esperado: esta es la fase de pulido. Usa 💻 Modo Código.

1. Que la grilla cobre vida

Usando framer-motion (ya instalado), anima la grilla del storefront.
- En src/pages/Home.jsx, envuelve la grilla en un contenedor motion que escalone a
  sus hijos (staggerChildren ~0.06s) al cargar.
- En src/components/ProductCard.jsx, convierte la tarjeta en un elemento motion:
  initial { opacity: 0, y: 16 } animando a { opacity: 1, y: 0 }, más un whileHover
  sutil (y: -4) y un whileTap. Mantén transiciones de ~200–300ms. No cambies la
  lógica de datos.

2. El momento de agregar a la reserva

Haz que agregar a la reserva se sienta bien con framer-motion:
1. En src/toast/ToastContext.jsx, envuelve la lista de toasts en <AnimatePresence> y
   haz que cada toast sea un motion.div que entra desde abajo con un spring
   (initial { opacity: 0, y: 20, scale: 0.9 } -> animate completo; exit de vuelta).
2. En src/components/Header.jsx, haz que el badge del carrito "salte" cuando cambia
   el número: dale key={count} y un pequeño rebote de escala al montarse.
3. En el botón "+" de la tarjeta, agrega un whileTap que lo achique al presionar.
Mantenlo rápido y elástico, sin rebotes de más.

3. Suaviza la página de producto y la confirmación

En src/pages/Product.jsx, anima la entrada con framer-motion: el thumbnail
aparece/escala desde la izquierda y la columna de detalle desde la derecha, en un
stagger corto. Agrega un whileTap al botón "Reservar para retiro".

En src/pages/Cart.jsx: anima las líneas con <AnimatePresence> para que quitar un
item se desvanezca/deslice. Cuando aparece la confirmación, que el check entre con
un spring y los detalles suban debajo. Rápido y prolijo.

Que el movimiento guíe, no que pelee por atención

Rápido (~150–300ms) y sutil. Pedile a Bob que respete prefers-reduced-motion para suavizar/desactivar el movimiento no esencial.

Criterios de éxito

  • Las tarjetas entran escalonadas con feedback de hover/tap.
  • Agregar a la reserva hace entrar el toast con spring y "saltar" el badge.
  • La página de producto entra suave; la confirmación tiene un estado animado.
  • Nada se siente lento; el movimiento es de buen gusto.

Parte 7 — Revisión y pulido

Tienes una tienda funcionando, animada y con asistente. La fase de revisión se asegura de que la app aguante más allá del camino feliz: que sea responsive, accesible y que los casos borde no la rompan.

Responsive y accesibilidad

Achicá el navegador a ancho de teléfono.

Asegúrate de que las tres pantallas sean responsive: la grilla colapsa a menos
columnas, el detalle de producto pasa de dos columnas a apilado, y la reserva apila
el resumen debajo de las líneas en pantallas chicas. Arreglá cualquier layout que
se desborde o superponga.

Después una pasada rápida de accesibilidad: cada thumbnail con texto alternativo
con sentido, botones y links como <button>/<a> reales con etiquetas claras, los
selectores y botones navegables por teclado, y que los estados de carga, reserva
vacía y "producto no encontrado" se rendericen sin errores. Lista qué cambiaste.

Después prueba los casos borde tú mismo:

  • Reserva vacía muestra su estado, no un resumen roto.
  • Producto sin stock (Sony WH-1000XM5) se renderiza bien y con el botón deshabilitado.
  • Cambiar de sucursal se refleja en la home, el producto y la reserva.
  • El asistente sigue apareciendo y respondiendo después de todos los cambios.

Reflexión

Mira el ciclo completo: Planificaste (mockups + contrato de datos → plan), Construiste (pantalla por pantalla desde una captura), Embebiste la inteligencia (el Asistente de watsonx Orchestrate), Puliste con animaciones y Revisaste responsive, accesibilidad y casos borde. ¿Dónde te ahorró tiempo el esqueleto pre-armado? ¿Dónde un prompt específico ganó contra uno vago?

Criterios de éxito

  • Las tres pantallas son responsive.
  • Accesibilidad y casos borde (vacío/error/sin stock) manejados.
  • El asistente sigue apareciendo y respondiendo después de los cambios.

Parte 8 — Documenta la app

El software no termina cuando funciona, termina cuando la próxima persona lo entiende. En esta parte vas a hacer que Bob genere un sitio de documentación con MkDocs.

Para ahorrar tiempo, el esqueleto ya está armado en el starter: requirements.txt (con mkdocs-material), la carpeta docs/ con una página por sección, y docs/images/ con los tres mockups ya copiados. Bob solo tiene que escribir el tema (mkdocs.yml) y completar el contenido de cada página.

1. Genera la documentación

En 💻 Modo Código, mandale este prompt a Bob:

Documenta este proyecto (Voltia) para un desarrollador nuevo como un sitio MkDocs.
El esqueleto YA EXISTE en el proyecto: requirements.txt (con mkdocs-material), la
carpeta docs/ con las páginas stub de abajo, y docs/images/ con home.png,
product.png y cart.png ya copiados. NO crees requirements.txt ni vuelvas a copiar
imágenes.

Lee src/ y documenta lo que REALMENTE hay — no inventes APIs. Referencia los
archivos fuente como código en línea (ej. `src/api/client.js`), nunca como links.

IMPORTANTE: el asistente embebido es de **watsonx Orchestrate**. Escribilo siempre
así, exactamente: "watsonx Orchestrate". NUNCA lo llames "watsonx Assistant".

Tu trabajo:
1. Crea mkdocs.yml en la raíz: tema Material, en los colores de Voltia (azul/cyan),
   con una nav que liste todas las páginas de docs/ de abajo.
2. Completa el contenido de cada una de estas páginas que YA existen (reemplaza su
   contenido stub):
   - docs/index.md            : qué es Voltia; un tour corto de features
   - docs/getting-started.md  : requisitos, instalación, npm run dev
   - docs/architecture.md     : SPA React + Vite, las rutas, el límite del cliente
                                de datos (src/api/client.js), el catálogo local
                                (src/api/catalog.js), carrito y sucursal globales, y
                                cómo embebemos el asistente de watsonx Orchestrate
   - docs/assistant.md        : cómo está embebido el agente (el <script> en
                                index.html, el div #wxo-root, rootElementID)
   - docs/screens/storefront.md, docs/screens/product.md, docs/screens/cart.md :
                                una página por pantalla. En cada una embebé arriba la
                                captura correspondiente desde ../images/ (home.png,
                                product.png, cart.png respectivamente).

No modifiques src/. No agregues dependencias nuevas a requirements.txt.

2. Ejecuta el sitio de docs

Abre una terminal nueva (deja npm run dev corriendo en la otra) y posiciónate en la carpeta voltia-starter. Después ejecuta los comandos uno por uno.

python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
mkdocs serve

python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
mkdocs serve

Abre http://localhost:8000. Deberías ver un sitio navegable y con buscador, documentando la tienda que construiste y cómo embebiste el asistente.
