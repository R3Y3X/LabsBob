Moderniza Java a la velocidad del negocio

Simple Pharmacy Management System es una aplicación web de operaciones farmacéuticas (recetas, pedidos, inventario de medicamentos, dashboards). Parte de Traditional WebSphere + Java 8 + Struts y se moderniza progresivamente hacia Liberty + Java 21 + React, con tests y remediación de CVEs.

5 + Alt-4 laboratorios
~90 minutos
40–48 BobCoins estimados

Cómo encajan los labs

Los Labs 1–3 forman el recorrido principal de modernización; los Labs 4, Alt-4 y 5 pueden hacerse en cualquier orden después. Cada lab usa Agent Mode con un prompt por fase (Análisis → Cambios → Validación) sobre carpetas snap* locales. Pegar el siguiente prompt de la página es el Continue; tu ok es el Approve.

Cómo trabaja Bob en cada lab

Todos los labs usan Agent Mode — el chat de Bob corre en un único modo de agente. No hay que cambiar de modo: comprueba que el indicador en la parte inferior del panel de chat dice Agent. Este recorrido usa prompts por fase en Agent Mode (Análisis → Cambios → Validación). Si activas el toggle Premium del portal, los Labs 1–5 pasan a los workflows nativos de Bob; el Lab Alt-4 sigue en Agent Mode. Al cambiar de carpeta snap*, Bob abre un chat nuevo — pega el primer prompt de ese lab.

Fase 1 — Análisis

Bob lee los archivos relevantes, identifica el estado actual y construye un inventario. Se detiene sin tocar archivos. El siguiente prompt de la página es el Continue.

Fase 2 — Cambios

Bob propone cada cambio de forma individual: muestra el diff completo, explica la razón, pregunta "¿Aplico el Cambio N?" y espera tu "ok" (nuestro Approve) antes de tocar cualquier archivo. Un cambio a la vez — nunca en batch.

Fase 3 — Validación

Cuando el último cambio esté confirmado, pegas el prompt de validación. Bob ejecuta mvn compile o mvn test, lee el resultado y — si hay errores — muestra el stack trace completo antes de proponer fixes.

Principio fundamental

Bob propone cada cambio significativo con una justificación y espera tu aprobación. Reporta el coste por tarea en BobCoins. Puede instalar un JDK faltante vía SDKMAN! si lo necesitas.

Si Bob aplica todo de golpe

Cada prompt de cambios pide diff + ok por cambio. Si Bob encadena cambios o salta a validación, interrumpe con:

STOP. Vuelve al protocolo del workshop:
- Un solo Cambio N por mensaje.
- Muestra el diff unified completo en el chat.
- Pregunta "¿Aplico el Cambio N?" y PARA hasta mi "ok" literal.
- No ejecutes mvn/git/npm ni pases a la siguiente fase sin mi permiso.
Empieza de nuevo mostrando el diff del Cambio que corresponda (sin aplicar nada más).

Camino recomendado

Los Labs 1 → 2 → 3 son la historia secuencial principal (cada uno consume la salida del anterior). Después del Lab 3, continúa con el Lab 4 y el Lab 5, o toma el Lab Alt-4 (TDD) como ejercicio independiente en cualquier momento. Tiempos orientativos (Agent Mode, entorno listo, basados en sesiones reales con Bob): Lab 1 ~15 min · Lab 2 ~15 min · Lab 3 ~25 min · Lab 4 ~20 min · Lab 5 ~12 min. Ruta completa Labs 1–5: ~90 min. Labs 1–3 solos: ~55 min. El Lab Alt-4 (~20 min) es opcional y no entra en los ~90 min. Reserva margen si revisas cada diff, tomas capturas o aparece troubleshooting.

2. Java + Maven

Elige tu sistema operativo. Reinicia Bob tras instalar Maven para que tome el PATH actualizado.

macOS

SDKMAN! — instala y cambia entre versiones de Java.

Ver comandos

Instala SDKMAN! y luego Java 8 (Lab 1), Java 21 (Labs 2+) y Maven. Para Apple Silicon usa Azul Zulu — Temurin no tiene build de Java 8 para arm64. Ejecuta cada comando en orden:

curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 8.0.504+1-zulu
sdk default java 8.0.504+1-zulu
sdk install java 21.0.12+1.1-zulu
sdk install maven

Gotcha Apple Silicon (serie M)

Temurin/Adoptium no tiene build Java 8 para arm64. Usa 8.0.504+1-zulu o sdk install java 8.0.472-amzn (Amazon Corretto). Para ver todos los builds Java 8 disponibles: sdk list java | grep " 8\."

Linux

SDKMAN! — igual que macOS.

Ver comandos

Instala SDKMAN!, Java 8 (Lab 1), Java 21 (Labs 2+) y Maven. Ejecuta cada comando en orden:

curl -s "https://get.sdkman.io" | bash
source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 8.0.504+1-zulu
sdk default java 8.0.504+1-zulu
sdk install java 21.0.12+1.1-zulu
sdk install maven

Ubuntu/Debian alternativo: sudo apt install openjdk-21-jdk maven

Windows

winget (PowerShell) o SDKMAN! en Git Bash/WSL.

Opción A — winget (PowerShell) 
winget install EclipseAdoptium.Temurin.8.JDK
winget install EclipseAdoptium.Temurin.21.JDK
winget install Apache.Maven

Cierra y reabre PowerShell. Apunta JAVA_HOME a Temurin 8 o 21 según el lab activo.

Opción B — SDKMAN! en Git Bash/WSL

Git Bash viene con Git for Windows. WSL: wsl --install en PowerShell de administrador. Luego usa los mismos comandos de macOS/Linux.

Bob puede instalar Java por ti

Si falta el JDK objetivo, Bob puede instalarlo vía SDKMAN! por su cuenta. Para un workshop con tiempo limitado, instalarlo de antemano sigue siendo la opción más segura.

3. Node.js (LTS) — solo Lab 3

Solo el Lab 3 necesita Node.js para el frontend React/Vite. Instala Node 20 o 22 LTS desde nodejs.org o con winget install OpenJS.NodeJS.LTS en Windows.

Libera los puertos entre labs

Un servidor Liberty dejado corriendo bloqueará el siguiente lab silenciosamente. Detén Liberty (Ctrl+C) antes de continuar.

Lab 1 usa el puerto 9080. Labs 2–5 usan 9081 (y a veces 9443). Si dudas, libera todos:

lsof -ti:9080,9081,9443 | xargs kill -9

Windows (PowerShell): mvn liberty:stop, o netstat -ano | findstr ":9080 :9081" y taskkill /PID <pid> /F.
