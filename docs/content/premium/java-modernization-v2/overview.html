El recorrido del workshop

El workshop está dividido en 6 labs independientes y secuenciales. Cada lab parte del estado que dejó el anterior. Haz clic en cualquier tarjeta para ir directamente a esa sección.

Cómo trabaja Bob en cada lab

Cada lab sigue el mismo ciclo de tres fases. Bob nunca modifica código sin tu aprobación — siempre muestra el cambio primero y espera tu confirmación.

Fase 1 — Análisis

Bob lee todos los archivos relevantes, identifica el estado actual, detecta problemas y construye un inventario. No toca ningún archivo todavía. Tú revisas el análisis y dices "adelante".

Fase 2 — Cambios

Bob propone cada cambio de forma individual: muestra el diff exacto, explica la razón y espera tu aprobación ("ok") antes de aplicarlo. Un cambio a la vez — nunca en batch sin aviso.

Fase 3 — Validación

Bob ejecuta el comando de validación (mvn compile, mvn test), lee el resultado y — si hay errores — muestra el stack trace completo antes de proponer cualquier fix. No arregla problemas a ciegas.

Principio fundamental

Bob aplica únicamente los cambios mínimos necesarios para el objetivo del lab. No refactoriza, no añade funcionalidades extras, no limpia código no relacionado. El control siempre es tuyo.

Recomendaciones antes de empezar

Regla crítica — carpeta raíz

Abre siempre la carpeta snap* específica del lab como raíz en Bob, nunca la carpeta padre. Si abres el directorio incorrecto, Bob analizará los archivos equivocados.

labs/lab1-java-liberty-replatforming/snapA-java-liberty-replatforming/  ← correcto
labs/lab1-java-liberty-replatforming/                                    ← incorrecto

Cambia JAVA_HOME antes del Lab 2

Los Labs 1 y 2 usan Java 8. A partir del Lab 3 debes cambiar a Java 21. Verifica siempre con java -version y mvn --version antes de ejecutar cualquier lab.

Prompt General de Rol

Cada lab incluye un prompt que establece el rol de Bob como experto en modernización Java. Pégalo al inicio de cada sesión antes del prompt del lab para obtener los mejores resultados.
