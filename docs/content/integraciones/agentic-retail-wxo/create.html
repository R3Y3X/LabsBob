Paso 1 — Preparar la CLI de watsonx Orchestrate

La CLI de Orchestrate es un paquete de Python. Aislarla en un entorno virtual evita que choque con otras versiones instaladas en tu equipo. Bob crea el entorno, instala la CLI y confirma la versión.

Prompt para Bob — crear el entorno e instalar la CLI

Estoy en la carpeta Lab2/confluent_agents de un workshop de watsonx Orchestrate.
Prepara mi entorno de trabajo usando la terminal integrada:

1. Crea un entorno virtual de Python llamado .venv en esta carpeta.
2. Actívalo. Si estoy en Windows, usa .venv\Scripts\Activate.ps1 en vez de source.
3. Con el entorno activo, actualiza pip.
4. Instala el paquete ibm-watsonx-orchestrate.
5. Ejecuta "orchestrate --version" y dime qué versión quedó instalada.

Reglas:
- Mantén esta misma terminal para todo el laboratorio; no abras una nueva.
- Si algún paso falla, detente ahí y explícame el error. No improvises
  soluciones alternativas ni instales paquetes que no te pedí.

Desde una terminal abierta en Lab2/confluent_agents, en este orden:

python3 -m venv .venv

Actívalo — en Windows PowerShell usa .venv\Scripts\Activate.ps1:

source .venv/bin/activate
python -m pip install --upgrade pip
pip install ibm-watsonx-orchestrate
orchestrate --version

✓ Checkpoint

  • Bob reporta una versión concreta de orchestrate, sin errores.
  • El prompt de la terminal muestra el prefijo (.venv).

Paso 2 — Preparar el archivo de configuración

El laboratorio centraliza en un solo archivo la URL de tu instancia, el endpoint del MCP compartido y tu API key. Ese archivo vive únicamente en tu equipo: no se versiona ni se comparte.

Prompt para Bob — crear workshop-config.env

Sigue en la misma terminal.

Copia workshop-config.env.example a workshop-config.env. No edites el .example.

Después muéstrame el contenido de workshop-config.env y dime exactamente qué
variables tengo que completar yo.

Importante: no inventes URLs, hosts ni claves, y no rellenes ningún valor por
tu cuenta. Espera a que yo complete el archivo con los datos del facilitador.
cp workshop-config.env.example workshop-config.env

Completa el archivo tú mismo

Abre workshop-config.env en el editor de Bob y rellena estas tres variables con los datos que te entregó el facilitador:

VariableQué va ahí
ORCHESTRATE_URLURL de tu instancia de watsonx Orchestrate.
RETAIL_MCP_SSE_URLEndpoint SSE del MCP retail compartido en la VM del workshop.
ORCHESTRATE_API_KEYTu API key de Orchestrate. Se queda en este archivo local.

RETAIL_MCP_TOOLKIT_NAME ya viene con el valor correcto (retail_availability_mcp) y debe coincidir con el nombre usado en los YAML de los agentes. No lo cambies.

Protege tu API key

La key vive solo en workshop-config.env, que no se versiona. Nunca la escribas en un YAML de agente, no la subas al repositorio, no la muestres en una captura de pantalla y no la pegues en el chat de Bob. En el paso siguiente Bob la lee de la variable de entorno, sin verla nunca en la conversación.

Paso 3 — Activar la instancia y verificar el toolkit MCP

Activar el ambiente apunta la CLI a tu instancia. Acto seguido conviene comprobar que el toolkit MCP compartido esté registrado: sin él, los agentes se importan pero no pueden consultar inventario.

Prompt para Bob — activar el ambiente y listar el toolkit

Ya completé workshop-config.env con la URL de mi instancia, el endpoint del MCP
y mi API key. Sigue en la misma terminal:

1. Carga las variables con: source workshop-config.env
2. Registra el ambiente:
   orchestrate env add --name workshop --url "$ORCHESTRATE_URL"
   Si el ambiente "workshop" ya existe, salta este comando y sigue.
3. Actívalo usando la variable de entorno, nunca el valor literal:
   orchestrate env activate workshop --api-key "$ORCHESTRATE_API_KEY"
4. Ejecuta: orchestrate toolkits list

Reglas importantes:
- No imprimas el valor de ORCHESTRATE_API_KEY en pantalla, ni con echo, ni en
  tu resumen. Refiérete a ella siempre como $ORCHESTRATE_API_KEY.
- Dime si aparece el toolkit "retail_availability_mcp" con la tool
  "get_sku_availability".
- Si NO aparece, detente y avísame. No ejecutes "orchestrate toolkits add"
  bajo ninguna circunstancia.
source workshop-config.env

Si el ambiente workshop ya existe, salta el siguiente comando:

orchestrate env add --name workshop --url "$ORCHESTRATE_URL"
orchestrate env activate workshop --api-key "$ORCHESTRATE_API_KEY"
orchestrate toolkits list

El toolkit no se registra desde tu equipo

El facilitador registra el MCP compartido una sola vez por instancia. Si retail_availability_mcp no aparece en la lista, detente y avísale. Registrarlo por tu cuenta con credenciales locales rompe el ambiente para el resto del grupo.

✓ Checkpoint

  • El ambiente workshop queda activo, sin errores de autenticación.
  • Aparece retail_availability_mcp con la tool get_sku_availability.
  • Tu API key nunca apareció impresa en la conversación con Bob.

Paso 4 — Importar el SKU Availability Agent

Este es el primero de los cuatro agentes. Su YAML conserva la lógica retail y referencia la tool get_sku_availability del toolkit remoto compartido — por eso el paso anterior tenía que confirmarse primero.

Prompt para Bob — importar el agente de disponibilidad

orchestrate agents import --file SKU_Availability_Agent.yaml
orchestrate agents list
🌐 Navegador watsonx Orchestrate

Paso 5 — Probar el agente en watsonx Orchestrate

Importar no es lo mismo que funcionar. Antes de seguir, entra a tu instancia y comprueba con tus propios ojos que el agente consulta inventario real a través del MCP.

  1. Abre tu instancia de watsonx Orchestrate en el navegador (la URL de ORCHESTRATE_URL).
  2. Ve a Agents y abre SKU_Availability_Agent.
  3. En Toolset, confirma que retail_availability_mcp:get_sku_availability esté vinculada.
  4. Haz clic en Deploy y confirma.
  5. Abre el chat de prueba del agente y envía la consulta de abajo.

Pregunta de prueba — pégala en el chat del agente

¿Cuánto stock hay de LAPTOP-DELL-XPS-15 en DOT Shopping?

Qué debes ver: una cantidad concreta para la sucursal que pediste, obtenida en tiempo real desde la tool get_sku_availability. Qué no debe pasar: el agente no debe inventar un número, ni mencionar Kafka, MCP o nombres internos de infraestructura.

✓ Checkpoint — no avances sin esto

  • SKU_Availability_Agent aparece desplegado en la UI.
  • La respuesta incluye una cantidad y la sucursal DOT Shopping.
  • En el detalle de la ejecución se ve la llamada a get_sku_availability.

Si el agente no encuentra la tool

Vuelve al Paso 3 y revisa la salida de orchestrate toolkits list. Si el toolkit compartido no está, avisa al facilitador — no lo registres desde tu equipo.
