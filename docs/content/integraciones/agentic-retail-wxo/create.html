Creación de Agentes~30 minMCP & Orchestrate

Preparar la CLI e importar el agente de disponibilidad

Activa la instancia, verifica el toolkit MCP compartido e importa el primer agente retail.

Paso obligatorio — antes de cualquier comando

Dónde estar parado

Abre una terminal en Lab2/confluent_agents. El MCP corre en la VM del workshop; tu laptop solo necesita la CLI y los YAML.

Terminal — cd a esta carpeta

Lab2/confluent_agents/

Paso 1 — Preparar la CLI de watsonx Orchestrate

1.1. Crear el ambiente virtual

Crea y activa el entorno virtual — ejecuta ambas líneas juntas, en la misma terminal

python3 -m venv .venv
source .venv/bin/activate

En Windows PowerShell, activa el ambiente con .venv\Scripts\Activate.ps1 en vez de la segunda línea de arriba.

Con el entorno activado, instala la CLI

python -m pip install --upgrade pip
pip install ibm-watsonx-orchestrate

Verifica la instalación — continúa solo cuando termine sin errores:

orchestrate --version

1.2. Cargar la configuración sin secretos

Duplica la plantilla y renómbrala — workshop-config.env.example nunca se edita directamente:

cp workshop-config.env.example workshop-config.env

Completa únicamente la URL SSE del MCP y la URL de tu instancia de Orchestrate en workshop-config.env. La API key no se guarda en este archivo ni en los YAML. Después cárgalo en la sesión:

source workshop-config.env

Configuración centralizada

RETAIL_MCP_SSE_URL identifica el MCP remoto y RETAIL_MCP_TOOLKIT_NAME identifica el toolkit compartido. El valor predeterminado del toolkit es retail_availability_mcp.

Paso 2 — Activar la instancia de Orchestrate

Usa la URL que te entregó el facilitador y activa un ambiente local llamado workshop.

orchestrate env add \
  --name workshop \
  --url "$ORCHESTRATE_URL"
orchestrate env activate workshop \
  --api-key <Orchestrate API Key>

Si workshop ya existe, ejecuta solamente el segundo comando (orchestrate env activate workshop --api-key <Orchestrate API Key>).

Protege la API key

No la pegues en el YAML, en workshop-config.env, en el repositorio ni en una captura de pantalla.

Paso 3 — Verificar el toolkit MCP compartido

El facilitador registra el toolkit una sola vez por instancia. Tú solo debes comprobar que está disponible:

orchestrate toolkits list

Debe aparecer retail_availability_mcp con la tool get_sku_availability. Si no aparece, avisa al facilitador; no ejecutes toolkits add desde tu laptop.

Paso 4 — Importar el SKU Availability Agent

El YAML conserva la lógica retail y referencia la tool del toolkit remoto compartido. Ejecuta:

orchestrate agents import --file SKU_Availability_Agent.yaml
orchestrate agents list

Confirma que aparece SKU_Availability_Agent. Todavía no pruebes el supervisor: primero importa el agente RAG en el siguiente paso.
