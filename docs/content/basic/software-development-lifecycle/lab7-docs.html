Lab 07 — Documentar la aplicación

4–8 BobCoins estimados
~25 minutos
5 pasos
1 modo de trabajo

El cierre del workshop. El software no está terminado cuando funciona: está terminado cuando la próxima persona lo puede entender. En este lab vas a crear un Modo Docs reutilizable para Bob y después usarlo para generar una carpeta docs/ completa para Bob's Beans y convertirla en un sitio de documentación con MkDocs — con la temática de la tostaduría, corriendo localmente.

Lo que vas a construir

  • Un Modo Docs personalizado en Bob, preparado para escribir documentación MkDocs.
  • Una carpeta docs/ en Markdown que documenta las pantallas, los datos y el sistema de diseño.
  • Un mkdocs.yml (tema Material en colores de café) y un requirements.txt.
  • Un sitio de documentación navegable en http://localhost:8000, con las capturas de los mockups embebidas.
Continúa el mismo workspace

Punto de partida

Sigue en bobs-beans-starter/ — no abras una carpeta nueva. Necesitas el Lab 06 completo: la aplicación está construida, animada y revisada.

Ya deberías tener esta carpeta abierta

bobs-beans-starter/
  • Python 3 instalado — verifica con python3 --version en la terminal integrada
  • MkDocs es una herramienta de Python; la vas a instalar en este lab

La documentación sí va en español

A diferencia de la interfaz de la aplicación, la documentación que genera Bob en este lab va en español. Los nombres de archivo, las rutas, las funciones y los fragmentos de configuración se mantienen en inglés, tal como están en el código.

Ejercicio

Vas a configurar un Modo Docs personalizado — una persona reutilizable de Bob preparada para escribir documentación — desde la configuración de Bob.

Abre Settings (el ícono de engranaje en el panel de Bob), ve a la pestaña Modes y haz clic en el botón + para crear un modo nuevo. Completa los campos en este orden:

Name📝 Docs

Después haz clic en Save. Elige 📝 Docs en el selector de modos (o escribe /mode docs) y úsalo para el resto del lab.

Los nombres de los campos quedan en inglés

La interfaz de Bob está en inglés, así que los campos del formulario (Slug, Name, Scope, Available Tools, …) aparecen tal cual en la pantalla. Lo que escribes adentro sí va en español.

Role definition (pégalo en el campo Role definition):

Eres un especialista en documentación para el proyecto Bob's Beans. Produces documentación
técnica clara y precisa en español, en formato Markdown, para un sitio MkDocs con el tema
Material.

Custom instructions (pégalo en el campo Mode-specific Custom Instructions):

- Un tema por página; una introducción corta y después secciones con prosa concisa.
- Usa admonitions (!!! note / tip / warning) para los destacados.
- Usa bloques de código con lenguaje declarado para cualquier código o comando.
- Lee siempre el código y referencia archivos y funciones reales; nunca inventes APIs.
- Referencia los archivos fuente como código en línea (por ejemplo `src/api/client.js`),
  nunca como links de Markdown.
- Mantén una navegación clara en mkdocs.yml y respeta la identidad visual de café del
  producto.
- Escribe la prosa en español. Los nombres de archivo, funciones, rutas, tokens y textos de
  la interfaz de la aplicación se mantienen en inglés, tal como están en el código.

Scope: proyecto o global

Project deja el modo dentro de este repositorio (en .bob/). Elige Global si quieres tener el Modo Docs disponible en todos tus proyectos futuros de Bob.

Paso 2 — Genera la documentación

En el 📝 Modo Docs, dale a Bob este prompt:

Documenta este proyecto para una persona desarrolladora que recién se suma, como un sitio
MkDocs. Lee src/ y documenta lo que realmente está ahí — no inventes APIs. Referencia los
archivos fuente como código en línea (por ejemplo `src/api/client.js`), nunca como links de
Markdown y nunca enlazando a números de línea.

Crea, en la raíz del proyecto:
- requirements.txt          : con "mkdocs-material"
- mkdocs.yml                : tema Material, adaptado a la estética de la tostaduría
                              (configuración más abajo)
- docs/index.md             : qué es Bob's Beans; un recorrido corto por sus funcionalidades
- docs/getting-started.md   : requisitos previos, instalación, la configuración de
                              .env / VITE_API_BASE_URL, npm run dev
- docs/architecture.md      : SPA de React + Vite, las rutas, el límite del cliente de API
                              (src/api/client.js), el carrito global (CartContext) y el toast
                              (ToastContext), y cómo fluyen los datos desde la API hasta las
                              pantallas
- docs/screens/storefront.md, product.md, cart.md : una por pantalla — propósito, qué función
                              de la API la alimenta, los componentes y las interacciones clave
- docs/data-and-state.md    : las funciones del cliente
                              (getProducts/getProduct/createOrder/imageUrl), los endpoints de
                              la API y los hooks de carrito y toast
- docs/design-system.md     : los tokens de Tailwind de café (coffee, espresso, cream, latte,
                              caramel, ink, muted, line, success) y las convenciones de
                              componentes

Copia las tres capturas de los mockups desde mockups/ hacia docs/images/, y embebe la
captura correspondiente al principio de cada página de pantalla:
storefront -> home.png, product -> product.png, cart -> cart.png.

Usa este tema en mkdocs.yml para que la documentación acompañe la estética de la tostaduría:
  theme:
    name: material
    icon: { logo: material/coffee }
    palette:
      - scheme: default
        primary: brown
        accent: deep orange
    features: [navigation.sections, navigation.top, content.code.copy, search.suggest]
  markdown_extensions: [admonition, pymdownx.superfences, pymdownx.highlight]
Agrupa las páginas de pantallas bajo una sección "Screens" en la navegación.

Escribe toda la prosa en español. Los nombres de archivo, las rutas, las funciones, los
tokens y los textos de la interfaz de la aplicación se mantienen en inglés.

Tu requirements.txt generado debería contener:

mkdocs-material

Paso 3 — Prepara el entorno de la documentación

Abre una terminal nueva en la raíz del proyecto, y deja npm run dev corriendo en la otra.

macOS / Linux

Crea y activa el entorno virtual en la misma terminal, en este orden

python3 -m venv .venv
source .venv/bin/activate

Con el entorno activado, instala las dependencias

pip install -r requirements.txt

Windows (PowerShell)

Crea y activa el entorno virtual en la misma terminal, en este orden

python -m venv .venv
.venv\Scripts\Activate.ps1

Con el entorno activado, instala las dependencias

pip install -r requirements.txt

Paso 4 — Ejecuta el sitio de documentación

Ejecuta en la terminal integrada

mkdocs serve

Abre http://localhost:8000. Deberías ver un sitio de documentación navegable, con búsqueda y temática de café, sobre la aplicación que construiste, con las capturas de los mockups en las páginas de pantallas.

Checkpoint

El sitio de documentación corre localmente sin advertencias, la navegación agrupa las páginas de pantallas, cada página muestra su mockup y el contenido refleja el código real (nombres de archivo y funciones del cliente correctos). El tema se lee como "café".

Paso 5 — Pulido

En el 📝 Modo Docs, pídele a Bob que lo ajuste:

Revisa la documentación generada contra el código real. Corrige cualquier imprecisión,
agrega una descripción corta del "flujo de datos" a architecture.md y asegúrate de que cada
página tenga una introducción de una línea.

Mantén la prosa en español y las referencias al código en inglés.

Solo local

Este sitio de documentación es para correr localmente (mkdocs serve) — no lo vamos a desplegar en ningún lado.

Solución de problemas

mkdocs: command not found

Verifica que el entorno virtual esté activado (deberías ver (.venv) en tu prompt) y después ejecuta pip install -r requirements.txt de nuevo. Como alternativa, ejecuta python -m mkdocs serve.

PowerShell no ejecuta Activate.ps1

Windows puede bloquear el script. En la misma ventana de PowerShell ejecuta Set-ExecutionPolicy -Scope Process -Bypass y vuelve a activar, o usa .venv\Scripts\activate.bat desde cmd.

mkdocs serve imprime advertencias 'link ... not found'

Bob convirtió referencias a archivos en links de Markdown hacia los archivos fuente. Pídele: "En la documentación, referencia los archivos fuente como código en línea, no como links de Markdown — quita los links a archivos y a números de línea." Vuelve a ejecutar mkdocs serve; debería quedar sin advertencias.

La documentación referencia archivos o funciones que no existen

Bob documentó de memoria en lugar de leer el código. Pídele que vuelva a verificar contra src/ y corrija los nombres.

  • Una carpeta docs/ con las páginas planificadas, generada a partir del código real.
  • mkdocs.yml usa el tema Material en colores de café; requirements.txt lista mkdocs-material.
  • Cada página de pantalla embebe su captura del mockup.
  • Un entorno virtual creado y las dependencias instaladas desde requirements.txt.
  • mkdocs serve corre sin advertencias y el sitio se puede navegar en http://localhost:8000.
