Qué hay oculto en este proyecto

El lab más corto del grupo

El escaneo en sí tarda segundos — es una búsqueda dirigida de CVEs, no una migración agéntica. La mayor parte del tiempo va en triaje: decidir qué hallazgos importan realmente y por qué.

Tres vulnerabilidades están plantadas deliberadamente. Bob debería encontrar las tres:

# Dependencia Versión vulnerable CVE / GHSA Severidad Versión de fix
1 commons-text 1.9 CVE-2022-42889 (Text4Shell) Critical (CVSS 9.8) 1.10.0
2 snakeyaml 1.30 GHSA-mjmj-j48q-9wg2 High 2.0
3 commons-lang3 3.11 GHSA-j288-q9x7-2f5v High 3.18.0

Qué hace cada una (léelo tras escanear)

  1. Text4Shell — CVE-2022-42889. StringSubstitutor en commons-text admite prefijos de interpolación más allá de la sustitución de variables — ${script:…}, ${url:…}, ${dns:…}. Si cualquier parte del mapa de sustitución contiene entrada controlada por un atacante, eso es ejecución arbitraria de scripts, exfiltración DNS o fetch de URLs. En esta app es alcanzable a través de LabelTemplateService, que renderiza etiquetas de dispensación de medicamentos desde una plantilla.
  2. SnakeYAML deserialization RCE — GHSA-mjmj-j48q-9wg2. El constructor por defecto new Yaml() instancia clases Java arbitrarias referenciadas en el YAML (p. ej. !!java.net.URL). Cargar YAML controlado por un atacante se convierte en instanciación arbitraria de clases y RCE potencial. Aquí es alcanzable vía FormularyLoader, que carga formulary.yaml para decidir categorías de medicamentos aprobadas.
  3. Commons Lang3 recursión no controlada — GHSA-j288-q9x7-2f5v. Ciertas entradas provocan recursión ilimitada y denegación de servicio por desbordamiento de pila. commons-text:1.9 arrastra commons-lang3:3.11 de forma transitiva; aquí está declarado explícitamente en esa misma versión para que el escaneo lo detecte y fije.

La forma de este problema importa

Dos de las tres solo son relevantes porque el código de la aplicación realmente las alcanza. La tercera es un problema puro del grafo de dependencias. El triaje real se parece exactamente a esta mezcla.

Vale la pena vigilar

  • Lab independiente — no depende de los Labs 1–3; usa prompts por fase en Agent Mode
  • Escaneo rápido y determinista — búsqueda dirigida de CVEs que termina en segundos
  • Alcance directo + transitivo — Bob resuelve el árbol de dependencias completo, no solo lo declarado en pom.xml
  • Flujo de remediación interactivo — cada CVE recibe un fix propuesto y un prompt de aprobación
  • Desglose de coste por tarea — incluso ejecuciones cortas muestran coste y contabilidad de tokens

Solución de problemas y ayuda

Solución de problemas

El escaneo reporta cero vulnerabilidades en la primera pasada

Es un resultado legítimo en un proyecto limpio — pero no en este. Significa que pom.xml no contiene las versiones vulnerables intencionadas. Verifica que abriste el snapshot de inicio snapE-* y no lo modificaste. pom.xml debería declarar commons-text:1.9, snakeyaml:1.30 y commons-lang3:3.11.

mvn compile falla tras un bump de versión

Una remediación actualizó una biblioteca a una versión con cambio de API incompatible. Pega el error de compilación a Bob y pídele que reconcilie — adaptará el código que llama o propondrá una versión alternativa aún segura. El upgrade a SnakeYAML 2.0 es el culpable más probable.

Una dependencia vulnerable es transitiva y no se actualiza limpiamente

El CVE vive dentro de una dependencia transitiva que Bob no puede simplemente actualizar, porque otra biblioteca requiere la versión antigua. Bob suele proponer un bloque <exclusion> en la dependencia externa más una declaración directa de la versión corregida. Aprueba cuando se te solicite.

La terminal de Bob muestra la versión incorrecta de Java

sdk use es por sesión de shell — no se aplica entre pestañas ni a la terminal que Bob abre por su cuenta. Ejecútalo en la terminal de Bob (macOS/Linux):

sdk use java 21.0.7-zulu

En Windows (PowerShell), asegúrate de que JAVA_HOME apunte a la instalación de Temurin 21 y reinicia la terminal.
