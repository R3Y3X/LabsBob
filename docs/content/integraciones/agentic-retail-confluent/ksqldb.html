El SQL que implementó Bob

Entender el SQL permite verificar que la lógica es correcta y ajustarla en proyectos reales.

Paso 1 — Stream de entrada: envuelve el tópico inventory.transactions como una vista SQL.

CREATE STREAM IF NOT EXISTS inventory_transactions (
  sku VARCHAR,
  branch VARCHAR,
  quantity INT
) WITH (
  KAFKA_TOPIC='inventory.transactions',
  KEY_FORMAT='KAFKA',
  VALUE_FORMAT='JSON'
);

Paso 2 — Tabla derivada: agrega disponibilidad sumando la columna quantity agrupada por SKU y sucursal. El resultado se escribe continuamente en inventory.availability.

CREATE TABLE IF NOT EXISTS inventory_availability WITH (
  KAFKA_TOPIC='inventory.availability',
  KEY_FORMAT='JSON',
  VALUE_FORMAT='JSON',
  PARTITIONS=1
) AS
SELECT
  sku,
  branch,
  SUM(quantity) AS available_quantity
FROM inventory_transactions
GROUP BY sku, branch
EMIT CHANGES;

¿Por qué EMIT CHANGES?

Le indica a ksqlDB que el resultado es un streaming continuo — cada nueva transacción recalcula y publica el stock actualizado de ese SKU/sucursal. Sin EMIT CHANGES sería una consulta de una sola vez.

Verificar el stream y la tabla en la UI

Ver el stream y la tabla en la interfaz confirma que ksqlDB los registró correctamente y están procesando mensajes.

  2. Selecciona el cluster activo.
  3. Ve a la pestaña Streams — verás INVENTORY_TRANSACTIONS con status Running.
  4. Ve a la pestaña Tables — verás INVENTORY_AVAILABILITY con status Running.

  • ksqlDB — ideal para agregaciones simples, filtros y joins sobre streams de Kafka con sintaxis SQL familiar. Perfecto para este lab: calcular stock disponible en tiempo real con pocas líneas.
