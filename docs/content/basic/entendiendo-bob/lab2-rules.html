Lab 1 — Rules

Convierte convenciones del equipo en instrucciones persistentes que Bob puede aplicar al trabajar en este proyecto.

3 rules persistentes
2–4 BobCoins estimados
5 pasos
1 modo de trabajo

Objetivos de aprendizaje

  • Distinguir una rule de un modo personalizado
  • Crear rules de proyecto en .bob/rules/
  • Comprobar que Bob aplica las rules al actualizar el README

Qué es una rule

Las rules son archivos de texto que Bob inyecta en todas las conversaciones, en todos los modos. Sirven para estándares de código, tono y restricciones de flujo, sin repetirlas en cada prompt.

Rules vs modo personalizado

Una rule no la pisa un modo personalizado. Si defines un monólogo interno como rule global, seguirá aplicándose aunque uses Ask, Agent o un modo que tú creaste. Las rules son el mecanismo transversal; las instrucciones del modo cubren solo ese modo.

Las rules de proyecto viven en .bob/rules/ y se versionan con el código: todo el equipo las hereda al clonar el repositorio.

Paso 2 — Rule de documentación

Añade esta línea a basic_rules.md. Así Bob documenta cada función pública que escriba o modifique, da igual la tarea.

Archivo: .bob/rules/basic_rules.md

Incluye siempre JSDoc conciso en cada función pública.

Paso 3 — Rule de comunicación

Añade la segunda rule. Controla cómo Bob formula respuestas y comentarios: útil si el equipo prefiere salida directa y corta.

Archivo: .bob/rules/basic_rules.md

Sé muy conciso en tus respuestas.

Paso 4 — Rule de monólogo interno

Añade la tercera rule. Produce un log persistente de lo que Bob ha hecho en todas las conversaciones: auditoría, continuidad entre sesiones y transparencia para el equipo.

Archivo: .bob/rules/basic_rules.md

Escribe un resumen de cada interacción en la carpeta `internal-monologue/`.
Nombra el archivo empezando por un timestamp, seguido de una descripción breve de la interacción.
Ejemplo: 2026-01-15_actualizar-readme.md
