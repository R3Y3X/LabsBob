Ciclo de Vida del Software con IBM Bob

Bob actúa como tu partner de desarrollo a lo largo del SDLC completo — planea la arquitectura en Plan Mode, implementa el código en Agent Mode, escribe y ejecuta pruebas con corrección automática de errores y genera documentación técnica — todo con compuertas de aprobación para que tú siempre tengas el control.

Plan → Código

Diseño antes de implementar

Bob usa Plan Mode para crear la arquitectura completa, el árbol de archivos y la lista de tareas antes de escribir una sola línea de código — eliminando el retrabajo costoso.

Test → Fix

Auto-corrección de errores

Bob genera pruebas, las ejecuta, lee el stack trace si falla, aplica el parche y vuelve a correr automáticamente — en bucle hasta que todos los tests pasan.

Docs automáticas

README + diagramas Mermaid

Bob genera documentación técnica precisa — no una plantilla genérica — porque conoce exactamente lo que construyó. README, diagramas y CHANGELOG en segundos.

El Ciclo Completo: Plan → Código → Tests → Documentación

Paso 1 Plan Mode — Arquitectura, árbol de archivos y lista de tareas. Sin código todavía.
Paso 2 Agent Mode — Implementación paso a paso con aprobación por diff. Instala dependencias y verifica que la API corre.
Paso 3 Agent Mode — Tests unitarios + bucle auto-corrección: genera → ejecuta → parchea → re-ejecuta hasta 0 fallos.
Paso 4 Agent Mode — README, diagrama Mermaid de arquitectura y CHANGELOG generados automáticamente.

Modos de IBM Bob en este Lab

Plan Mode

El Arquitecto — Paso 1

Genera el plan completo del proyecto: árbol de archivos, descripción de arquitectura y lista de tareas ordenadas. Sin editar ningún archivo hasta que apruebes el plan.

  • Diseño antes de implementar
  • Análisis de edge-cases y dependencias
  • Cero ediciones hasta aprobación

Agent Mode

El Implementador — Pasos 2, 3 y 4

Crea la estructura de archivos, escribe el código, instala dependencias, genera y ejecuta tests, y produce documentación. Cada escritura requiere tu aprobación explícita.

  • Creación de archivos con diff visible
  • Bucle test → fix automático
  • Aprobación requerida para escrituras

Ask Mode

El Consultor — Opcional

Si durante el lab tienes dudas sobre el código generado — explicaciones de la lógica, diagramas adicionales, análisis de dependencias — usa Ask Mode. No modifica nada.

  • Explica código sin modificarlo
  • 270k tokens de contexto
  • Lectura auto-aprobada

Requisitos Previos

IBM Bob 2.1 IDE

IDE de IBM Bob instalado y API key configurada. Completa primero el lab Hands-on Inicial.

Python 3.10+ y pip

El proyecto de ejemplo usa FastAPI y pytest. Verifica con python --version y pip --version.

Git configurado

Git disponible en tu terminal. Verifica con git --version.

Auto-aprobación: OFF en la primera ejecución

Revisa cada paso que Bob propone, especialmente cuando modifica requirements.txt o ejecuta comandos en terminal.

Importante: revisión de comandos

En Bob 2.1 puedes editar un comando terminal antes de ejecutarlo. Aprovecha esta capacidad para revisar y ajustar los comandos de instalación de dependencias antes de confirmar.

Reglas y Consideraciones

✅ Buenas prácticas

  • Revisa el plan completo en Plan Mode antes de aprobar
  • Inspecciona cada diff antes de confirmar en Agent Mode
  • Deja que Bob complete el bucle test-fix sin interrumpir
  • Activa auto-aprobación sólo en pasos que ya comprendiste

❌ Evitar

  • Confirmar diffs sin leerlos
  • Interrumpir el bucle de tests a mitad
  • Modificar archivos manualmente mientras Bob trabaja
  • Saltar el Paso 1 (Plan Mode) e ir directamente al código
