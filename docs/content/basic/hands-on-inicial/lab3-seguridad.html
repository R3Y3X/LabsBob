Escenario

Galaxium Travels es una aplicación que creció durante varios años en un codebase complejo. Una revisión manual de seguridad consume tiempo y produce resultados inconsistentes entre miembros del equipo. Necesitas un proceso repetible que genere salida estructurada que los desarrolladores puedan actuar de inmediato y que alimente un pipeline de remediación automatizado.

En este lab usarás IBM Bob para crear un skill de auditoría basado en OWASP ASVS, ejecutarlo contra Galaxium Travels, generar un reporte SARIF y producir un OSCAL Plan of Action and Milestones (POA&M) que Bob puede usar para guiar la remediación.

Alcance de la auditoría

Este lab audita contra ASVS Level 1 en control de acceso (V4), validación de inputs (V5), seguridad de API (V13) y configuración (V14). El mismo patrón de skill funciona con cualquier estándar: reemplaza los controles ASVS por CWE Top 25, un checklist interno u otro framework.

Ejercicio: Auditoría ASVS con skills y reportes estructurados

Paso 1 — Crear el skill de auditoría

Un skill es un conjunto de instrucciones reutilizable que Bob sigue para una tarea específica. Vas a crear asvs-audit para auditar Galaxium Travels contra OWASP ASVS Level 1.

  1. Bajo el chat, haz clic en Bob - Settings → Bob Settings.
  2. Haz clic en Skills en la barra lateral.
  3. Haz clic en + para crear un skill nuevo.
  4. Skill Name: asvs-audit (se invoca con /asvs-audit en el chat).
  5. Description:
Audita un codebase contra OWASP ASVS Level 1 en control de acceso, validación de inputs, seguridad de API y configuración.
  1. Activa Allow Bob to use this skill para que Bob pueda invocarlo cuando un plan o prompt lo requiera.
  2. Scope & Location: selecciona el proyecto galaxium-travels para guardar el skill en .bob/skills/ y versionarlo con el codebase.
  3. Pega las instrucciones completas del skill en Skill Instructions:
---
name: asvs-audit
description: Audit a codebase against OWASP ASVS Level 1 access control, input validation, API security, and configuration requirements and produce structured findings ready for SARIF and OSCAL export.
user-invocable: true
---

Perform a structured security audit of this codebase. Work through the following phases in order. Do not skip phases or combine them.

## Phase 1: Discover
Read and understand the application before auditing. Focus on:
- Entry points: main files, route definitions, controllers
- Authentication and session handling code
- Input validation and sanitization code
- Database query code
- Any files flagged as high-risk in earlier analysis

Summarize what you find before proceeding to Phase 2.

## Phase 2: Audit
Check each control below. For each one record: PASS, FAIL, or N/A.
For every FAIL, record the file path and line number.

### V4.1 General Access Control
- V4.1.3 — Users can only access their own resources; other users' data is not accessible
- V4.1.5 — Access control denies by default — unauthenticated requests are rejected

### V4.2 Operation Level Access Control
- V4.2.1 — Sensitive resources cannot be accessed by manipulating a predictable object ID (IDOR protection)

### V5.1 Input Validation
- V5.1.1 — All string inputs have defined maximum length constraints

### V13.1 Generic Web Service Security
- V13.1.3 — API endpoints do not accept credentials or PII in URL query parameters

### V14.4 HTTP Security Headers
- V14.4.1 — HTTP responses include appropriate security headers such as Content-Security-Policy, X-Frame-Options, and X-Content-Type-Options

### V14.5 HTTP Request Header Validation
- V14.5.3 — CORS origin is validated against an explicit allowlist — wildcard origins are not permitted

## Phase 3: Generate Findings
For each FAIL, produce a finding in this format:

**Finding [N]:**
- Rule: ASVS [control number]
- Severity: Critical / High / Medium / Low
- File: [path]
- Line: [number or range, if identifiable]
- Issue: [one sentence describing what was found]
- Fix: [one sentence describing the recommended change]

## Phase 4: Summary
Produce a short summary:
- Total controls checked
- Pass / Fail / N/A counts
- Two-sentence overall security posture assessment

Save the findings to the location specified by the plan or prompt that invoked this skill. Do not generate SARIF, OSCAL, or other report files — report generation is a separate task. Report that the audit is complete and wait for the next instruction.

Haz clic en Create.

Paso 2 — Identificar áreas de alto riesgo (Ask Mode)

Para ahorrar tokens, pide a Bob que identifique los archivos y carpetas más relevantes para seguridad antes de ejecutar el skill de auditoría.

  1. Abre el chat de Bob si no está visible.
  2. Selecciona Ask en el selector de modos.
  3. Envía este prompt:
Explore this codebase as a Senior Security Analyst. Give me a short summary covering:
1. The primary tech stack and framework
2. Identify the files and folders most relevant to security

Make sure to also review:
1. How authentication and session management are handled
2. How user input is accepted and validated
3. Where database queries are made
4. Any API endpoints that accept external input

I want to understand the highest security risk areas before running an audit.

Salida esperada

Bob lee los archivos y responde con un resumen de la estructura de la aplicación y las áreas de mayor riesgo.

Paso 3 — Crear el plan de auditoría (Plan Mode)

Cambia a Plan Mode y pide a Bob un plan para auditar las áreas de alto riesgo identificadas.

Create a plan for auditing the high-risk areas found in the previous
exploration.

When auditing, use the asvs-audit skill to guide the process.

When the plan runs, create the security/ directory if it does not exist and
save the findings to security/audit-findings.md

Save the plan to plan/audit-plan.md

Bob puede hacer preguntas de seguimiento sobre el alcance. Puedes responderlas o indicar use your recommendation.

Abre plan/audit-plan.md para revisar el enfoque de auditoría antes de ejecutarlo.

Paso 4 — Ejecutar la auditoría (Agent Mode)

  1. Haz clic en + para iniciar una tarea nueva.
  2. Selecciona Agent Mode.
  3. En Permissions, activa Read, Edit, Execute y Skill. Deja el resto desactivado.
PermisoEstadoPor qué
Read✅ OnBob lee el codebase, el plan y el skill
Edit✅ OnBob escribe los hallazgos en security/audit-findings.md
Execute✅ OnBob puede ejecutar comandos para confirmar estructura de archivos
Skill✅ OnEl plan invoca el skill asvs-audit
MCP❌ OffNo necesario para análisis local de código

Pide a Bob que implemente el plan:

Implement the @plan/audit-plan.md

Revisa los hallazgos en security/audit-findings.md.

Ventana de contexto

Guardar los hallazgos en un archivo te permite iniciar un chat nuevo y generar reportes sin releer todo el codebase. En codebases grandes, audita una categoría ASVS a la vez (V4, luego V5, V13, V14) y pide a Bob que consolide al final.

Agent Mode requiere aprobación

Cada escritura de archivo mostrará un diff para que lo revises antes de confirmar.

Paso 5 — Generar reporte SARIF (Agent Mode)

SARIF es el formato estándar de intercambio para resultados de análisis estático. IDEs, GitHub Advanced Security y la mayoría de pipelines CI/CD lo consumen directamente.

  1. Inicia una tarea nueva con +.
  2. Usa Agent Mode.
  3. En Permissions, activa Read, Edit y Execute. Deja Skill y MCP desactivados.
@security/audit-findings.md

Generate a SARIF 2.1.0 report from the audit findings.
Save it to `security/audit-results.sarif`.

Include:
- Tool name: "ASVS Security Audit"
- A rule entry for each ASVS control that was checked, with the control ID and description
- A result entry for each finding, with severity level, file path, line number, and the fix recommendation in the message field

Salida esperada

El archivo security/audit-results.sarif debe contener un array runs con entradas results, una por hallazgo. Bob suele mapear Critical/High → SARIF error y Medium/Low → SARIF warning.

Paso 6 — Generar plan de remediación OSCAL POA&M (Agent Mode)

El POA&M OSCAL es un documento JSON legible por máquinas que mapea cada hallazgo a una tarea de remediación estructurada. Bob puede leerlo como cola de trabajo y aplicar correcciones sistemáticamente.

  1. Inicia una tarea nueva con +.
  2. Usa Agent Mode.
  3. En Permissions, activa Read, Edit y Execute.
@security/audit-findings.md

Generate an OSCAL Plan of Action and Milestones (POA&M) from the audit findings.
Save it to `security/poam.json`.

For each finding include:
- A unique UUID
- The ASVS control ID as the finding reference
- Severity and a one-sentence risk description
- A concrete remediation task with enough detail for an AI agent to implement it without additional context — include file path, line reference, and the specific change required
- A milestone label based on severity: Critical and High findings get "sprint-1", Medium and Low get "sprint-2"

Use OSCAL version 1.1.2 structure.

Al terminar tendrás dos artefactos en security/:

  • audit-results.sarif — hallazgos estructurados para tooling y CI/CD
  • poam.json — cola de remediación para asistencia humana o por IA

Paso 7 — Revisar y priorizar hallazgos (Ask Mode)

  1. Inicia una tarea nueva con +.
  2. Selecciona Ask Mode.
  3. Envía este prompt:
@security/poam.json

Review this remediation plan and identify the 3 most critical items to fix first.

For each one include:
- What the vulnerability is and why it is the highest priority
- Which file and line to look at
- What the fix involves and roughly how long it would take a developer to implement
