Use ~/Documents/bob/confluent-agents as the working directory.

Step 2 — Create the ksqlDB Stream & Derived Topic

Bob creates a ksqlDB cluster on Confluent CLI and defines the stream and aggregation table that continuously calculates inventory availability from raw transactions.

Bob Prompt — Agent Mode

The inventory.transactions topic has fields: sku, branch, quantity, transaction_type.
Transaction types are ADDITION (positive quantity) and SALE (negative quantity).
Create a ksqlDB cluster through Confluent CLI, then create a stream from the topic
and an inventory_availability table aggregating available_quantity by sku and branch.

Expected Output

Bob runs the Confluent CLI commands to create the ksqlDB cluster (takes ~2 minutes to provision), then creates the inventory_transactions stream and inventory_availability table. Running SELECT * FROM INVENTORY_AVAILABILITY EMIT CHANGES; in the Confluent UI shows the aggregated data.

Step 4 — Import the MCP Toolkit into watsonx Orchestrate

Import the sku-availability-checker MCP toolkit into watsonx Orchestrate using the ADK CLI. Update the .env file with your ksqlDB credentials first.

CLI Command

orchestrate toolkits add \
  --kind mcp \
  --name "sku-availability-checker" \
  --description "Real-time inventory checker using Confluent Kafka and ksqlDB" \
  --language python \
  --package-root "/absolute/path/to/confluent-agents" \
  --command "python3 get_sku_availability.py" \
  --tools "*"

Expected Output

The toolkit is registered in watsonx Orchestrate. Open the Orchestrate UI → Manage Tools → verify sku-availability-checker appears with its get_sku_availability tool listed.

Step 5 — Import the Agents and Upload the Product Catalog

Import the three agents via YAML definitions and upload the product catalog as a knowledge source for the Substitute Finder Agent's RAG capability.

CLI Commands — Import Agents

cd ~/Documents/bob/confluent-agents

# Import the SKU Availability Agent
orchestrate agents import -f SKU_Availability_Agent.yaml

# Import the Substitute Finder Agent
orchestrate agents import -f Substitute_Finder_Agent.yaml

# Import the Store Associate (supervisor) Agent
orchestrate agents import -f Store_Associate_Agent.yaml

Upload Product Catalog (RAG)

In the watsonx Orchestrate UI: Knowledge → Add New Knowledge → Upload Files → select product-catalog.docx. Set the name to enterprise_documents. Wait for indexing to complete before testing.

Step 6 — Test the End-to-End Agent Flow

Test the complete system with two queries: one for an out-of-stock item (should trigger RAG substitute search) and one for an in-stock item (should return availability directly).

Test A — Out of Stock (triggers substitute search)

Do you have LAPTOP-DELL-XPS-15 in MallOfEgypt?

Expected Output — Test A

The Store Associate Agent routes to SKU Availability Agent → detects 0 stock → routes to Substitute Finder Agent → returns: "LAPTOP-DELL-XPS-15 is currently out of stock in MallOfEgypt. Similar alternatives: LAPTOP-HP-SPECTRE-X360 (available) — same processor class, memory tier, and usage profile."

Test B — In Stock

Do you have LAPTOP-MACBOOK-PRO-16 in MallOfEgypt?

Expected Output — Test B

The Store Associate Agent routes to SKU Availability Agent → detects stock > 0 → returns directly: "LAPTOP-MACBOOK-PRO-16 is available in MallOfEgypt with X units in stock." No substitute search is triggered.
