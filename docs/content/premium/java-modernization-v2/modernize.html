Modernize — Java Upgrade & Liberty Replatforming

Five steps: Bob analyzes your codebase, upgrades Java and dependencies, replatforms to Liberty, validates with a full test cycle, and generates governance documentation.

Step-by-Step Guide

Step 1 — Start the Java Upgrade Workflow

Open your Java project in the Bob IDE. Launch the Java Upgrade workflow from the Start Workflow button or via the /start-java-mod skill command. Bob will ask clarifying questions about your target Java version and project build tool.

Bob Prompt — Agent Mode

Java Upgrade

Alternative — Natural Language

Analyze my Java project and create an upgrade plan from Java 11 to Java 21 LTS.
Identify all dependency compatibility issues, Spring Boot version conflicts,
and configuration changes needed. Use Maven.

Expected Output

Bob scans the project and returns: list of dependencies requiring updates, incompatible APIs flagged (e.g., javax.* → jakarta.* for Jakarta EE), Spring Boot version recommendation, and an ordered task list. Bob creates a checkpoint commit before any changes.

Step 2 — Bob Analyzes Dependencies and Identifies Issues

Bob performs a deep dependency analysis — checking transitive dependencies, Maven/Gradle configurations, Spring Boot compatibility, and flagging vulnerable libraries. This phase replaces weeks of manual detective work.

Expected Output

Bob presents a dependency report: grouped by severity (Breaking / Warning / Info), with specific version recommendations for each artifact. Example: "spring-boot-starter-parent: 2.7.x → 3.2.x required for Jakarta EE compatibility." Review and approve the upgrade plan.

💡 Why this replaces manual analysis

Traditional Java modernization teams spend 60–70% of project time mapping what exists before touching code. Bob's telemetry-driven prioritization surfaces breaking changes, transitive conflicts, and subtle configuration shifts before they become production problems — in minutes, not weeks.

Step 3 — Implement the Upgrade: Code & Config Updates

Bob executes the approved upgrade plan — updating pom.xml dependencies, migrating javax imports to jakarta, updating Spring Boot configurations, and removing deprecated annotations. Every change is an atomic, reviewable diff.

Bob Prompt — Agent Mode

Implement the approved upgrade plan:
1. Update pom.xml with the new dependency versions.
2. Migrate all javax imports to jakarta equivalents.
3. Update Spring Boot configurations for 3.x compatibility.
4. Remove deprecated annotations and patterns.
Validate with a Maven build after each major change.

Expected Output

Bob applies changes file by file, showing each diff. After updating pom.xml, Bob runs mvn compile to surface any remaining issues. It iterates until the build succeeds. A real-world example (Novacomp): a senior architect completed a full enterprise REST API modernization in 2 days using this workflow.

Step 4 — Run the Build-Test-Diagnose-Fix Cycle

Bob runs the full test suite, diagnoses any failures, applies fixes, and re-runs until all tests pass. This closed-loop cycle ensures modernization progresses with quality validation at each step.

Bob Prompt — Agent Mode

Run the full test suite with Maven. Fix any test failures automatically
and re-run until all tests pass. Generate a test coverage report
using JaCoCo and a test summary report.

Expected Output

Bob runs mvn test, reads any failures, patches the affected classes, and re-runs. Final output: all tests pass + JaCoCo coverage report showing coverage percentage. Bob also flags any classes with 0% coverage as candidates for test generation.

Step 5 — Generate Documentation & Verify

Bob generates a complete modernization record — README, changelog, architecture diagram, and a summary of all changes made. This documentation supports governance, auditability, and team handoff.

Bob Prompt — Agent Mode

Generate complete modernization documentation:
1. An updated README.md with the new Java version, build steps, and deployment notes.
2. A MODERNIZATION.md listing all changes made, the rationale, and the risks mitigated.
3. A Mermaid architecture diagram showing the updated component structure.
4. A final verification: run the application and confirm it starts successfully.

Expected Output

Bob creates all documentation files and runs a final application startup validation. Bob's session summary lists every file changed, every test fixed, and every library upgraded — a complete audit trail for the modernization.
