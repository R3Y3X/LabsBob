Java y Maven

El Lab 1 arranca en Java 8 (Zulu). Desde el Lab 2 hace falta Java 21 (Semeru). Instala las dos versiones y Maven ahora. Después de instalar, cierra y vuelve a abrir Bob para que tome el PATH nuevo.

Elige tu sistema operativo. Solo un botón queda activo y ves únicamente esos comandos, a todo el ancho.

Si aún no tienes Homebrew, instálalo primero. Método oficial:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Si el comando anterior falla, descarga el instalador y ejecútalo de forma local:

curl -fsSL -o install.sh https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh
/bin/bash install.sh

Usa la app Terminal con zsh (el shell por defecto). SDKMAN! instala y cambia entre Java 8 Zulu, Java 21 Semeru y Maven:

curl -s "https://get.sdkman.io" | bash

Cierra y abre de nuevo Terminal, o carga SDKMAN! en esta sesión:

source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 8.0.504+1-zulu
sdk default java 8.0.504+1-zulu
sdk install java 21.0.12-sem
sdk install maven

Apple Silicon

Temurin no tiene Java 8 para arm64. Por eso usamos Zulu, que sí corre en Intel y en Macs de la serie M.

Instala primero las herramientas de base y después SDKMAN!:

sudo apt update && sudo apt install -y bash curl zip unzip lsof
curl -s "https://get.sdkman.io" | bash

Abre una terminal nueva, o carga SDKMAN! ahora:

source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 8.0.504+1-zulu
sdk default java 8.0.504+1-zulu
sdk install java 21.0.12-sem
sdk install maven

Elige una opción y quédate en ella todo el workshop. No mezcles PowerShell nativo con WSL.

Opción A — PowerShell + WinGet 
winget install --id Azul.Zulu.8.JDK --exact
winget install --id IBM.Semeru.21.JDK --exact
winget install --id Apache.Maven --exact

Cierra y vuelve a abrir PowerShell y Bob. Para el Lab 1, JAVA_HOME apunta a Zulu 8; antes del Lab 2, cámbialo a Semeru 21.

Opción B — PowerShell + curl.exe (sin WinGet)

Si winget no está o falla, usa curl.exe (va con Windows 10/11). Descarga los MSI de Zulu 8 y Semeru 21, y el ZIP de Maven. Ejemplo de instalación:

curl.exe -L -o "$env:TEMP\zulu8.msi" "https://cdn.azul.com/zulu/bin/zulu8.88.0.19-ca-jdk8.0.462-win_x64.msi"
Start-Process msiexec.exe -Wait -ArgumentList '/i', "$env:TEMP\zulu8.msi"

Repite el mismo patrón con el MSI de Semeru 21. Para Maven, descomprime el ZIP en C:\Tools\maven y añade C:\Tools\maven\bin al PATH de usuario. Cierra y abre PowerShell y Bob.

Opción C — WSL 2 + SDKMAN!

En PowerShell como administrador:

wsl --install

Abre Ubuntu/WSL — no PowerShell — e instala primero las herramientas de base, luego el mismo stack que en Linux:

sudo apt update && sudo apt install -y bash curl zip unzip lsof
curl -s "https://get.sdkman.io" | bash

Después, en una terminal WSL nueva:

source "$HOME/.sdkman/bin/sdkman-init.sh"
sdk install java 8.0.504+1-zulu
sdk default java 8.0.504+1-zulu
sdk install java 21.0.12-sem
sdk install maven

Deja el workshop en el sistema de archivos de WSL y abre Bob en el contexto WSL. Todos los comandos sdk, java, mvn y npm salen de esa terminal.

Comprueba Java 8 antes del Lab 1

java -version
javac -version
mvn --version

Los tres deben reportar Java 8 (1.8). Maven lo instalas tú; si falta el JDK, Bob puede instalarlo con SDKMAN!, pero en un taller cronometrado conviene tenerlo listo.

Cambia a Java 21 antes del Lab 2

Los Labs 2–5 (y el frontend del Lab 3) usan Semeru 21. Haz el cambio antes de abrir snapB-java-upgrade. No esperes a que el workflow lo pida.

macOS, Linux o WSL:

sdk default java 21.0.12-sem
java -version

Windows (PowerShell): apunta JAVA_HOME al JDK Semeru 21 (la ruta exacta depende del instalador) y confirma java -version y javac -version. Cierra y vuelve a abrir Bob.

Una terminal nueva no basta si Bob ya estaba abierto

sdk default y JAVA_HOME los toma el proceso de Bob al arrancar. Tras cambiar de 8 a 21, cierra Bob por completo y ábrelo de nuevo sobre la carpeta snap* del lab.

Node.js 22 — Lab 3

El frontend React del Lab 3 necesita Node.js 22 (con npm). Instálalo ahora para que el preflight pase; el Lab 3 lo usa de verdad.

macOS, Linux o WSL:

curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.6/install.sh | bash
source "$HOME/.nvm/nvm.sh"
nvm install 22
nvm use 22

Windows nativo (PowerShell) con WinGet:

winget install --id OpenJS.NodeJS.22 --exact

Windows sin WinGet — MSI oficial con curl.exe:

curl.exe -L -o "$env:TEMP\node-v22.msi" "https://nodejs.org/dist/v22.20.0/node-v22.20.0-x64.msi"
Start-Process msiexec.exe -Wait -ArgumentList '/i', "$env:TEMP\node-v22.msi"

Cierra y vuelve a abrir PowerShell y Bob. Comprueba node -v (debe empezar por v22) y npm -v.

Preflight — comprueba el entorno

Ejecuta estos comandos en la misma clase de terminal que vas a usar en los labs (zsh en macOS, bash en Linux/WSL, PowerShell en Windows nativo). En Windows, curl es curl.exe y ssh viene con OpenSSH opcional.

java -version
javac -version
mvn --version
node -v
npm -v
curl --version
ssh -V

Antes del Lab 1, java y javac deben ser 8. Antes del Lab 2, cámbialos a 21 y vuelve a correr java -version y javac -version. node y npm hacen falta en el Lab 3.

Libera los puertos entre labs

Si dejas Liberty o Vite en marcha, el lab siguiente puede engancharse a esa instancia. El Lab 1 usa el puerto 9080; los Labs 2–5 usan 9081 (y a veces 9443). El Lab 3 también usa 3000 (Vite).

macOS, Linux o WSL:

lsof -ti:9080,9081,9443,3000 | xargs kill -9

PowerShell de Windows:

Get-NetTCPConnection -LocalPort 9080,9081,9443,3000 -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force }
