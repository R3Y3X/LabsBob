Step 3. Publicar 20 mensajes de ejemplo

Los 20 mensajes simulan ventas y reposiciones reales de Voltia, para que los agentes del Lab 2 encuentren datos desde el primer momento.

¿Qué hace setup.sh -s 3 internamente?

Entra a la VM vía SSH y ejecuta produce_messages.py desde un pod Python dentro del cluster. El script produce 20 mensajes al tópico inventory.transactions usando las credenciales SASL del .env. Cada mensaje incluye:

  • Campos sku, branch, quantity, transaction_type, timestamp, source y reference — alineados con el schema Protobuf registrado en Step 1b.
  • Variedad de tipos: ADDITION, SALE y ADJUSTMENT — para que ksqlDB calcule disponibilidades reales.
  • En cuanto llega el primer mensaje, INVENTORY_AVAILABILITY empieza a actualizar su tabla en tiempo real.

Para ejecutar los 3 pasos de una vez: ./setup.sh (sin flags). Para empezar de cero: ./setup.sh -c.

Pega el siguiente prompt en Bob (en la misma conversación, ya tiene SSH y .env activos):

Flujo completo — los mensajes publicados en inventory.transactions son procesados por ksqlDB y el resultado llega a inventory.availability en tiempo real:

Consulta la tabla de disponibilidad directamente desde el endpoint externo de ksqlDB:

curl -sk -u admin:<KSQLDB_PASSWORD> \
  https://<VM_IP>/ksqldb/query \
  -H "Content-Type: application/vnd.ksql.v1+json" \
  -d '{"ksql":"SELECT * FROM INVENTORY_AVAILABILITY LIMIT 5;","streamsProperties":{}}'

Deberías ver 5 filas con sku, branch y available_quantity.

4b. Verificar los mensajes en la consola web

  1. En la consola web, navega al tópico inventory.transactions y haz clic en la pestaña Messages o Live Tail.
  2. Configura el visor para leer desde el inicio: selecciona From Beginning / Earliest en el selector de offset.
  3. Haz clic en cualquiera de los mensajes para abrir el panel de detalle y verifica:
    • Offset y Partición — confirma en cuál de las particiones se almacenó el evento.
    • Timestamp — fecha y hora exacta de emisión registrada por el broker.
    • Payload (cuerpo) — comprueba que el JSON incluye los campos sku, branch, quantity, transaction_type y timestamp.
  4. Navega también al tópico inventory.availability y verifica que ksqlDB ya calculó filas con available_quantity actualizada.

✓ Checkpoint 4 (Final)

  • Se visualizan los 20 mensajes en la pestaña Messages con sus timestamps y offsets correctos.
  • El JSON del payload coincide con la estructura del schema registrado en Step 1b.
  • El tópico inventory.availability muestra disponibilidad calculada por SKU y sucursal.

Lab 1 completo — Criterios de éxito

  • Tópico inventory.transactions — 1 partición, retention infinita.
  • Stream INVENTORY_TRANSACTIONS y tabla INVENTORY_AVAILABILITY creados en ksqlDB.
  • Schema InventoryTransaction registrado en Schema Registry con versión v1.
  • Tópico inventory.availability se actualiza automáticamente con cada transacción.
  • 20 mensajes publicados en inventory.transactions y visibles en la consola web.

Troubleshooting — Errores frecuentes

Referencia rápida para resolver los problemas más comunes durante el workshop.

Síntoma / Error Causa probable Solución inmediata
Permissions 0644 for .pem are too open Permisos incorrectos en la llave SSH. Ejecuta chmod 600 cflt-vsi-key.pem o indícaselo a Bob.
Connection timed out al puerto SSH (22) IP incorrecta o Security Group / Firewall bloqueado. Verifica la IP pública activa en la consola de IBM Cloud y que el puerto 22 esté habilitado en el Security Group.
Schema validation failed al publicar mensajes El JSON del evento no coincide con los tipos definidos en el Schema. Asegúrate de que quantity sea entero (no string) y que transaction_type sea uno de: ADDITION, SALE, ADJUSTMENT.
Topic already exists El tópico ya fue creado en un intento previo. El script lo detecta y lo omite sin error. Si deseas empezar de cero ejecuta ./setup.sh -c para limpiar el entorno.
No se ven mensajes en el Web UI El filtro de mensajes está en Offset Actual en lugar de Inicio. Cambia el selector de visualización a From Beginning / Earliest en la pestaña Messages del tópico.
